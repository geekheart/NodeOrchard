# 工作流编辑器：编辑、运行和学习

新版工作流使用 schema 2。旧流程保留原执行语义，进入后可明确选择升级；升级后应重新检查端口和输入资料。工作流必须通过界面搭建、配置和连接，开发回归中的临时测试图不代替界面验收。

## 日常操作

1. 在“编辑”视图拖入节点，或双击画布搜索。端口可拖拽连接，也可依次点击输出和输入。连线可插入节点；“自动布局”按依赖整理画布。
2. 输入节点定义文件、文件夹、图片、文字和数字字段；左侧“输入资料”选择本机资料。文件匹配规则必须唯一命中，缺失或歧义会阻止运行。
3. 工具、代码、Skill 和子流程都可作为能力节点。Skill 从实际安装列表选择并固定版本；子流程选择已保存工作流并固定内容快照。
4. 使用具名输入端口合并分支。必需输入就绪后执行节点；没有依赖关系的节点按并行限额执行。共享资源有独立限额。
5. 点击“检查输入”完成预检后运行。运行时仍会重新检查来源，防止检查后文件被替换。输入草稿可保留，预检结论不会跨刷新沿用。
6. 在“运行”视图查看节点状态、输入、输出、日志和中途产物。可打开本次输出文件夹、预览或下载图片。局部重跑会保留历史版本，重做所选节点及受影响后继。

## 人工审核

产图能力后放置“人工审核”节点，将图片分支的后续能力接在审核输出后。图片生成后立即保存并展示。已登记的 AI 产图工具强制要求审核；自定义代码和 Skill 新生成的图片也会检查审核路径。

审核提供“通过”“要求修改”和“停止”操作。要求修改需要反馈和明确的上游能力目标，例如负责排版的 Skill；只重画同一份固定计划不会改变规划。每次反馈触发一次有上限的修订，再次等待人工决定。执行模式的修订不更改 Skill 正文和版本。

审核等待不占模型调用和运行准入名额。应用重启后可以继续持久等待；重启时正在执行、外部结果未确认的能力标为未知，不盲目重放。

## 触发与输出

手动和定时使用同一份输入定义、文件选择和预检。定时设置只增加时间、时区和重叠规则；保存定时任务前先准备资料，触发时重新核验。上一次同计划仍在等待人工审核时跳过重复触发。

默认输出到应用管理的目录；可选择允许范围内的自定义根目录。每次运行、节点和尝试有独立目录及来源清单。输出节点可以放在流程中途，保存结果后继续向后传递，不要求所有成果集中到终点。

## 学习

“编辑/运行”是界面视图，“执行/学习”是运行方式，两者独立。业务主链始终按执行任务设计；学习需通过明确的产物对比和 Skill 改进节点绑定目标。

学习支持训练集与验证集、逐轮样例结果及通过率。训练和验证使用本批次冻结的只读 Hermes 记忆；优化提示不包含验证输入和答案。普通执行仍保留原有 memory 更新机制。实际产图样例也必须等待人工审核后才能继续；持久恢复只恢复原批次快照，不重新采集当前记忆。

## 边界

- 子流程、逐项处理和条件循环采用固定子流程及次数上限；不支持任意回边造成无限循环。
- 文件预检检查输入资料的可读性和完整性，具体业务正确性仍由选定的 Skill、代码和人工验收确认。
- 并行受资源限额约束；占用同一受限资源的节点按限额执行。能力失败只阻塞其后继，独立分支可继续完成。
- 旧实现的专业学习放行证明不能自动视为新实现已通过，迁移后的产物需要重新验收。
