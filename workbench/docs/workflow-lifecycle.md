# 工作流归档、回收站与删除

工作流按固定顺序管理：**工作流 → 已归档 → 回收站 → 永久删除**。这些状态独立于执行/学习模式和运行状态。

| 当前区域 | 卡片「⋯」操作 | 结果 |
| --- | --- | --- |
| 工作流 | 归档工作流 | 进入已归档，停用关联定时任务 |
| 已归档 | 恢复到工作流 | 恢复编辑与运行；定时任务保持停用 |
| 已归档 | 移入回收站 | 进入回收站，仍可恢复 |
| 回收站 | 恢复到已归档 | 恢复至归档区，仍只读 |
| 回收站 | 永久删除工作流 | 输入完整名称后删除流程定义，不能恢复 |

归档和回收站内可以只读查看节点、历史输入输出及产物，也可以导出流程。编辑、保存、运行、学习、局部重跑和定时启用均被阻止。恢复时重新读取服务端当前定义后才解锁，浏览器中的旧草稿不会自动覆盖它。

永久删除保留历史运行、学习记录、反馈、暂停的定时快照和已生成文件，不做磁盘清理。历史快照和旧浏览器缓存不会使被删除的流程重新出现在看板。删除流程后，其关联定时任务不能直接重新启用。

流程仍有准备、排队、执行、学习或人工审核等待时，先完成或停止这些任务，才能归档。界面提示和服务端都检查，异步文件预检、Skill 读取及定时触发期间也会在真正启动前再次核对状态。

每次管理操作都携带当前版本号，重复或过期请求会提示刷新；永久删除只能从回收站提交，并要求完整名称逐字匹配。菜单和弹窗支持键盘操作、取消、Esc 及焦点返回。

看板搜索仅作用于当前区域，数量显示当前命中数和区域总数。存在搜索或状态条件时，始终显示“清除筛选”，即使命中结果也能一键清空。看不到已有工作流时，先检查搜索词、状态筛选及当前区域。

## 验证范围

自动测试覆盖归档、回收、恢复、永久删除、应用重启后的持久化，以及旧缓存、过期版本、等待审核和定时触发的状态检查。实际运行结果以当前测试输出为准；本机业务验收日志与截图保存在被忽略的工作环境中。
