# 第二版工作流的输入、产物与等审核恢复

这些能力用于 `schemaVersion: 2` 的工作流；旧版串行文档和历史运行保留原有行为。

## 输入准备与定时绑定

固定任务可以将需求保存在输入节点的 `config.defaultValue`。运行未提供值或文本为空白时采用默认值；本次显式提供的非空值、数字 `0` 与布尔值 `false` 保持原样。旧入口的 `config.value` 保留兼容读取，显式 `defaultValue` 优先。手动运行、预检、调度和实际执行使用相同的默认值解析，默认值也进入本次固定输入快照。必需资料没有输入且没有默认值时才阻止执行。

输入节点通过 `config.fields` 声明资料表单：

```json
{
  "fieldName": "materials",
  "fields": [
    { "key": "project", "label": "工程文件", "kind": "file", "required": true, "extensions": [".epro2"], "match": "*.epro2" },
    { "key": "front", "label": "正面照片", "kind": "image", "required": true, "role": "front" }
  ]
}
```

字段类型为 `file / folder / image / text / number`，最多 32 项。手动运行和保存定时任务前使用同一预检接口；真正创建运行时再次检查，不能把上次预检的通过当作本次输入正确的证据。

文件匹配可以绑定一个目录，也可以明确选择符合模式的文件。绑定目录时必须恰好命中一个文件，多个匹配不会自动取第一份。预检结果保留目录绑定，实际启动时才把唯一文件解析为固定执行路径，生成本次输入清单。后续轮询检查发现匹配不再唯一、文件被替换或目录内容发生变化，会停止消费这些资料，要求重新准备运行。

`workflow_file_runs` 保存原始绑定、解析后的输入、来源 SHA、图片尺寸和清单摘要；输出根目录中的 `输入清单.json` 是可读副本。它冻结的是输入引用和内容摘要，不会自动复制用户选择的整个资料目录。来源原件在运行期间需要保持不变。

通用预检检查路径、可读性、扩展名、图片文件头和尺寸、必填项、匹配歧义及输出位置可写性。硬件工程的业务正确性由已登记能力继续检查：例如四文件准备能力复读真实 epro2 ZIP、PCB 身份、照片 SHA／尺寸、校准来源和审核标记，再允许进行原生导出；完整针脚映射仍需要原生证据。

本地浏览器只访问已配置工作区及用户的文稿、桌面、下载、图片目录。隐藏目录、凭据文件及越界符号链接不能通过浏览器读取。单文件上限 512MB；资料目录最多 1000 个文件、2GB 和 8 层，超过时需缩小资料范围。

定时触发使用保存的文档和输入绑定，启动仍经过 `prepareRun`。应用未运行而错过的触发不会补跑；Hermes 离线的 Skill 任务记录离线并跳过；同一计划上一任务待人工审核时，后续触发记录跳过原因，避免重复生成候选图。

## 中间产物和输出位置

默认位置为 `workspaceRoot/outputs/工作流名/运行ID/节点ID/版本-N/`。用户可指定输出根目录；每次运行、节点和修改次数仍各自隔离，不直接覆盖旧候选。输出目录不能位于本次整目录输入之内，避免输出反过来污染来源清单。

能力返回实际存在的文件路径，由工作台登记为 opaque 产物 ID。预览和下载只接受产物 ID，不提供任意路径读取 URL。读取时重新核对真实路径和 SHA；已登记文件被修改后，原预览、原审核与复用引用失效。保存、预览和交付节点可以位于中间位置，不以唯一最终输出节点定义工作流是否结束。

Skill 会话本身仍位于受管理工作区。输出到用户自定义根目录时，执行器按已声明的文件端口或 `artifacts / files / path` 回执确定性搬运实际文件并登记摘要，不因输出根目录而放开任意 Hermes 工作目录。代码／工具能力直接使用本次节点的 `context.outputDirectory`。

## 人工审核与重启

图片人工审核是工作台执行状态，与 Hermes 的工具权限审批分别处理。审核记录绑定产物 ID 和 SHA；通过后启动消费节点前仍会核对产物和来源，防止批准后文件被替换。修改请求只重跑指定生产能力及受影响后继，保留每个候选和修改意见，并受修改次数限制。

普通执行处于纯人工等待、没有在途能力时，可以关闭并重开工作台后继续审核。正在执行的模型／工具结果若未确认，仍记为 `unknown`，不会自动重放外部动作。

含人工节点的新学习批次会在任何样例开始前持久化原 Hermes 内置 `memory / user` 提示块及两个启用标记。私有文件位于 `workspaceRoot/.workbench-learning-memory/批次ID.json`，目录权限 0700、文件权限 0600；学习记录仅保存版本与摘要，不在接口回传记忆正文。

只有同时满足以下条件，学习控制器才保留等审核检查点：

- 子运行确实为 `waiting_review`，且没有运行中、准备中或 Hermes 交互中的能力。
- 子运行、样例、轮次和只读 memory scope 均属于原学习批次。
- 原始持久记忆快照凭据完整。

重开后先连接 Hermes；恢复 RPC 按旧摘要复读原快照，重建同一只读对象，再接回原样例运行。它不会新建记忆锚点、读取当前 memory、重跑已经完成的样例或自动批准图片。旧快照缺失、被篡改或已释放时拒绝恢复，要求停止该批次或重新开始学习。旧版本启动、没有持久凭据的学习记录也不会追补采集当前记忆冒充原快照。

训练、验证及评价调用继续使用批次开始前的同一只读上下文；外部 memory provider、持久写入及后台记忆总结保持禁用。验证样例结果参与独立评分，不能进入 Skill 优化提示。恢复完成后也保留这个边界。正常执行模式继续保留原来的记忆更新机制。

学习成功或被正式释放后，快照文件改写为不含记忆正文的释放标记，旧摘要失效。运行中的工具或模型调用、反馈候选编辑等非人工等待状态不做推测性恢复。

## 验证范围

自动测试覆盖真实临时 SQLite、文件与目录预检、匹配往返、产物篡改、HTTP 审核阻塞、定时重复跳过、独立 Python 网关进程退出／重启后的旧记忆恢复，以及控制器在训练样例中途等审核重启后继续原运行。测试中不会连接真实模型或启动 EDA／CAD；真实工程、图片效果和专业验收需要另行记录实际运行证据。
