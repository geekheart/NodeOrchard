# 总控源码自修复（实验性）

此能力用于修复工作台自身的软件问题。它默认关闭，仅用户可在“设置 → 助手权限 → 总控助手”开启“源码自修复（实验性）”。开启后，总控可通过受控源码工具修改允许的文件、运行隔离相关测试并记录结果；独立工作流助手与只读委派不取得这些能力。该开关不授权修改、运行或重跑用户真实工作流。

## 人工权限与工具

“读取诊断源码”使用独立 `supervisor.sourceRead` 开关，默认关闭。开启后开放 `app.source.list/read/search`，不需要开启 `sourceRepair`，也不授予补丁、修复测试、历史备份或回滚权限。具备维护所需读取权限时，可通过 `maintenance.experiment` 在只读源码副本运行明确的相关测试，见[总控持续维护](application-maintenance.md#隔离验证与权限)。读取范围为受控仓库源码与下列固定Hermes诊断模块；已开启修复时继续兼容读取。只有用户可修改这些开关，旧设置缺失字段投影为false而不写回。

`supervisor.sourceRepair` 默认为 `false`，由现有人工设置入口保存。助手不能开启、维持或恢复自己的权限；目录、调用和执行阶段均需检查当前身份及权限，旧聊天、工具结果与修复记录不代替当前准入。

源码修复操作方法由按权限加载的内部 Skill `repair-application` 提供；默认关闭时不引入该 Skill 正文，普通诊断与结果验证只保留条件指针。工具、当前权限和服务端校验仍为能力边界。

开启权限后，修复、测试和回滚仍绑定当前总控对话的人工要求；只读排查、否定或引用中的修复文字不会授权写入。用户明确要求修复后，总控可在允许范围内完成修改和相关测试，无需逐文件改为人工操作。

| 工具 | 用途 |
| --- | --- |
| `app.source.list` / `app.source.search` / `app.source.read` | 发现允许文件、按literal符号定位行号，再读取当前内容与版本身份 |
| `app.source.patch` | 按预期 SHA 与稳定操作 ID 写入受限源码，保留修改前备份和回执 |
| `app.source.test` | 在源码副本与临时数据中运行显式选择的相关 Node 测试 |
| `app.source.history` | 读取修复、测试和回滚记录 |
| `app.source.rollback` | 校验当前文件为该次修改后的版本或已恢复原版，再按备份回滚 |

`app.source.read` 先对完整源码脱敏并保留原行数，再按每页最多1800字符返回，低于助手工具结果的压缩阈值；脱敏占位符重复处理不再扩写，分页不切断占位符。`endLine`、`readLineCount` 表示实际返回范围。`truncated=true` 时使用返回的 `nextStartLine` 与 `nextStartColumn` 继续读取；长行可能停在同一行，不能只递增行号。行与列从1开始，列按脱敏正文的UTF-16位置计数。每页保留完整文件SHA，文件变化后重新定位；到达末尾时两个续读游标均为 `null`。这只改变只读分页，不增加源码写入权限。

### 固定Hermes诊断模块

`read` 必须在仓库 `path` 与固定 `component` 中恰选一项；`search` 的 `component` 与仓库 `prefix` 互斥，省略二者仍搜索仓库。`component` 仅接受下表五项，不接受安装目录或SDK路径。

| component | 安装目录内的逻辑文件 |
| --- | --- |
| `codex-stream` | `agent/codex_runtime.py` |
| `provider-call` | `agent/chat_completion_helpers.py` |
| `request-client` | `agent/client_lifecycle.py` |
| `client-factory` | `agent/agent_runtime_helpers.py` |
| `gateway-output` | `tui_gateway/prompt_turn.py` |

根目录由工作台启动配置提供；逐段拒绝链接，核对打开文件身份、大小、UTF-8及读取前后的版本。每个文件上限256KiB，只读内容经完整脱敏后分页或字面量搜索。返回 `origin: hermes-installed`、组件、逻辑相对文件及原文SHA，不返回本机安装路径。缺失、变化或不受支持的安装布局明确拒绝，不导入或执行Hermes来补齐。

仓库和固定模块共用源码显示规则：源码中的推理标签字面量先转义为 `&lt;think>` 等形式，再完整脱敏，返回 `sourceMarkupEscaped: true`；普通诊断及会话的推理过滤保持原样。搜索仍输入源码原有字面量，例如 `<think>`，在原行匹配后对显示文本归一，普通符号不受影响。行号保留，列按最终展示文本计数；SHA始终指向原文。脱敏或显示转义后的片段不能无条件当作完整原文件用于补丁，写入仍须经过已有路径、原文SHA及替换校验。

这些内容说明当前安装源码可能采取的分支，不能代替该次调用的实际分支或生效重试配置。读取接口不读取Hermes配置、认证、环境文件或任意SDK源码；未知配置保持未知。组件和原生逻辑路径均不能用于 `patch`，固定读取器本身也受源码保护。

工具只处理工作台允许的源码范围；权限和工具准入相关实现、凭据、`.git` 及用户数据目录固定保护。路径、来源与版本校验由服务端执行，不接受任意本机路径或 shell 命令。业务代码候选仍走工作流原有提案、应用与运行入口，不能借此修改应用源码。

独立会话升级使用的 `application-conversation-hub.mjs`及其范围回归同属准入保护文件，源码修复也不能改写升级身份或解除来源绑定。总控子诊断始终只读，即使人工开启源码修复也不取得补丁或测试工具。

源码服务需要能核对 Git 仓库状态，读取以已登记源码为限。启动时已有且不能归属本修复的改动会拒绝覆盖；仓库状态不可核对、版本过期或备份不完整时，按工具返回的具体原因停止，不改用工作流代码节点绕过。

## 修复与验证

1. 先用已有诊断接口读取相关错误、请求与版本证据；确定软件问题后，再通过源码目录和读取工具定位最小修改范围。
2. 写入时提交读取所得的预期 SHA 和稳定 `operationId`。内容已变化则停止并重新读取；重复请求按原身份核对，不使用新操作 ID 掩盖未确认结果。备份与记录保存后才进行修改，工具回执不等于修复通过。
3. 选择与改动相关的显式测试文件，通过 `app.source.test` 验证。测试在源码副本和临时数据目录中运行，使用操作系统沙箱关闭网络并限制文件访问；没有有效沙箱时拒绝运行，不退回宿主直接执行。测试入口不接受任意命令、不安装依赖，也不启动真实工作流或模型验收。
4. 通过修复历史核对实际修改、测试退出状态和失败信息。只有相关测试实际通过，才可报告相应验证通过；指出未覆盖的界面或业务行为。失败、取消或结果未知均保留记录，不能当作成功或自动重放。
5. 说明改动的生效方式：前端资源需刷新页面，后端模块由用户手动重启工作台。当前工具不自动重启、安装依赖或发布。

修改后源码可能影响程序后续行为。工具外围的路径、权限、备份和测试约束不能证明任意新程序绝对安全；隔离测试通过也不证明真实工作流、外部服务或所有场景已经恢复。业务代码运行器原有的可信宿主执行边界不因本功能改变。

当前内置测试执行器仅支持 macOS Seatbelt，启动前实际探测网络和目录隔离、Node 子进程是否符合约束。其它平台或探测失败返回不可用。测试只能选择 `workbench/test/` 下显式的 `.test.mjs` 文件，通过固定 `node --test` 运行；不支持任意程序、Python／编译器子进程或通配符全量运行。真实业务或模型仍活动时拒绝启动测试，不为腾出测试环境停止用户运行。测试前后核对修复文件 SHA 和完整源码副本清单；源码变化时结果不能沿用为当前版本已通过。

## 记录与回滚

每次源码修改、隔离测试及回滚保留可追溯记录，包含操作身份、文件前后版本和实际状态。源码备份、差异和测试详情留在私有修复记录中，不混入通用应用日志或用户工作流历史。分级日志只保存允许的阶段、身份、状态与计数，见[应用日志](application-logging.md)。

多文件写入逐项复核版本，发生中断或失败时保留已写入文件和部分结果记录，不宣称文件系统整体原子提交。回滚按原修改后的 SHA 核对当前文件；已恢复原版可幂等确认，文件后来被用户、其它修复或更新改成其它版本时拒绝覆盖，需先人工检查差异。回滚源码不撤销已发生的外部副作用，也不改写工作流、审核或产物记录。

用户可在设置页查看记录，并在关闭开关后继续手动回滚；关闭后，AI 不能再写源码、调用 `app.source.test` 或回滚。独立 `sourceRead` 下的维护测试继续使用只读验证准入，保留历史不构成写入权限。对真实业务现场的修复和重新运行仍需各自明确授权与原有校验。
