# 总控持续维护

维护任务用于在原总控主题保存排错目标、阶段、证据摘要和隔离实验回执，跨轮继续处理软件问题。它不替代工作流执行器，也不增加源码或权限设置的写入能力。任务始终绑定真实人工消息、总控主题及可选的工作流／普通运行；学习材料、其它主题和模型自行提交的身份不能成为操作授权。

## 接口与续接

`maintenance.task` 登记或读取任务、保存检查点、请求人工源码权限、继续及停止；`maintenance.experiment` 启动单节点复现或相关源码测试，并按实验身份回读状态和分页输出。具体字段以这两个工具的当前 schema 为准，处理器位于 `src/application-maintenance.mjs`；两类执行分别位于 `application-maintenance-reproduction.mjs` 和 `application-maintenance-verification.mjs`。

开始和实验使用稳定操作身份；推进核对当前任务修订。相同来源消息不重复创建任务，相同已准入实验读取原回执，不因模型重问、刷新或重启重新执行。运行中进程中断后保留 `unknown`，先核对已有证据，不能换操作 ID 把未知结果重放。任务摘要和实验输出有界、脱敏；需要详情时分页读取，不将全部历史灌入每次模型请求。

阶段分为诊断、复现、修复和验证。每段模型工具预算耗尽只表示本段结束；保存证据和下一项缺口后，使用任务状态继续，不能把聊天回复完成当作修复完成。`waiting_permission` 等待人工设置，`waiting_continue` 等待续接，`unknown` 表示结果尚未确认，`stopped` 表示已停止。任务状态和聊天、业务运行、审核状态分别保存。

## 隔离验证与权限

| 操作 | 准入和范围 |
| --- | --- |
| 持久诊断、实验回读 | 总控当前工作流读取和软件日志权限；绑定工作流时继续核对对象范围 |
| `reproduce` | 另需工作资料读取；固定已保存文档或普通运行中的一个支持节点，使用默认输入或该运行的冻结输入，核验并复制已登记普通素材 |
| `verify` | 另需工作资料及独立 `sourceRead` 权限；只在当前源码副本运行明确选择的相关 `workbench/test/*.test.mjs`，无需开启 `sourceRepair` |
| 源码修改、修复测试与回滚 | 继续走默认关闭的人工 `sourceRepair` 开关和原 `app.source.patch/test/rollback`；维护任务不能代开权限 |

单节点复现执行冻结代码或已校验候选副本，不应用到原工作流。支持范围以实际处理器为准；Skill、未支持的注册工具、学习运行及输入不足明确不可用，人工审核保持等待。实验不调用业务模型、不访问网络、不安装依赖；基础 JavaScript、Python 标准库及已探测的本地软件仍须满足各自执行条件。

复现和源码测试都要求实际验证的 OS 沙箱，源码／输入副本只读，写入限制在实验临时目录。平台不支持或隔离探测失败时返回 `unavailable`，不退回宿主直接执行。停止、权限变化和执行预算到期保留真实终态；执行预算不等于给模型等待重新添加本地截止。实验产物按独立实验身份、大小和 SHA 回读，不冒充原运行交付。

需要修改软件时，`request-source-repair` 只记录原因与 `#/settings` 入口。用户手动开启后仍须在原总控主题明确继续；设置变更、旧消息、检查点及只读升级都不授权自动补丁。独立助手升级的总控诊断继续锁定来源和只读边界，不能因人工开启源码修复而变成可写子任务。源码操作的保护范围、CAS、备份与回滚以[总控源码自修复](application-source-repair.md)为准。

## 完成标准

`verified` 只证明回执所列隔离范围通过，`candidate_verified` 只证明候选副本通过，均不表示原工作流已应用、运行或业务验收成功。源码修复另需核对修复记录、相关测试终态及当前源码版本；旧快照通过不能代表当前文件。失败、超时、取消、`stale`、`unavailable` 或 `unknown` 均不能报告已修好。

结论列明验证对象、快照／输入身份、实际测试、产物与未覆盖行为。只运行相关测试，不修改或重跑原工作流，不代批审核。自动化验收使用隔离数据与合成决策；本机沙箱、真实模型和用户业务验收分别说明，不能互相替代。
