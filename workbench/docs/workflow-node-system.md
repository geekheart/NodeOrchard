# 工作流节点体系

节点分为基础节点、派生节点、组合节点。派生节点从基础节点或已有派生节点形成具有特定用途、工具配置、业务代码或固定 Skill 的特色节点，并明确记录直接父级。业务能力复用 Hermes Skill、工具／代码节点及个人派生节点；内置派生只提供通用文本与 JSON 工具。节点颜色继续由基础类型的分类决定。

## 基础语义

Skill 节点可声明 `requiredToolsets` 请求 Hermes 图片、浏览器、Computer Use 或已配置 MCP；这是依赖声明，不授予权限。Skills 页与选择器提供人工创建入口，媒体输出经真实文件登记和人工审核，规则见[Skill 图片与外部工具](skill-integrations.md)。

共 14 类：输入／触发、校验、AI／Skill、工具／代码、子流程、数据整理、汇总、条件判断、逐项处理、条件循环、人工审核／补充、产物输出、产物对比、学习改进。后两类是学习支线，普通执行跳过。当前 AI／Skill 入口调用固定版本 Hermes Skill，不增加独立模型和记忆实现。

“学习改进”可选择指定 Skill、工具／代码或整个业务工作流；范围及目标由该节点固定，候选遵守输入、评价、审核和来源边界，见[学习范围与候选校验](learning-protocol.md#学习范围与候选校验)。

并行由依赖、运行并发上限和资源占用决定，不增加并行节点。手动和定时共用同一输入契约。现有重跑、人工修改反馈、来源核验和记忆隔离继续由公共运行机制管理。

校验节点用具名字段路径检查 required、nonempty、type、equals，通过后原样传递输入；失败保留每条检查结果、阻止下游，不调用模型。路径只能读取自身数据，不读取原型字段。文件存在性、扩展名和来源哈希仍由输入资料预检负责；具体业务规则由用户选择的 Skill 或代码负责。

产物输出可以选择阶段产物或最终交付。阶段产物在节点完成时即保存，并可继续传递。运行记录的 outputs 保留全部输出，stageOutputs 单列阶段结果，output 汇总最终结果。旧文档没有显式用途时保留原有行为。图片预览支线不等于批准；生成图片仍须存在人工审核路径，未经审核不能流入生产能力或显式最终交付。

## 节点派生

节点库“节点派生”包含个人与内置派生节点。选中基础节点或派生实例后，以当前配置保存一个新的特色节点；其名称、用途、端口、工具／代码和固定 Skill 共同形成不可变的版本。所有已注册工具通过同一个元数据入口生成内置派生节点，保留原有端口、资源与强制图片审核属性。内置节点只读，可继续派生为个人节点。

### 父级与版本

- 从基础节点派生，父级为该基础类型；例如“文稿清理”派生自“工具／代码”。
- 从已有派生节点继续派生，父级为该节点的固定版本；例如“简短文稿清理”派生自“文稿清理 · v2”。同时保留基础类型，避免把特色名称当成新的执行器。
- 给同一派生节点发布新版本，沿用原父级。发布版本不会把自己登记为自己的父级，也不会让旧实例自动升级。
- 旧记录缺少直接父级时显示“父级未记录”，基础类型仍可显示。读取兼容只投影未知状态，不补造父级或改写历史。

派生定义和目录记录保存 `parent`。基础父级为 `{ kind: "foundation", baseType, title }`；派生或组合父级为 `{ kind: "preset" | "component", id, version, title, baseType }`。旧记录的未知投影为 `{ kind: "unknown", baseType }`。每份记录只保存直接父级快照，不递归嵌入整棵来源树。

新派生必须给出明确父级；引用派生或组合父级时，本机目录须存在该固定记录和版本，名称、种类、基础类型必须一致。导入节点的父级尚未在本机登记时，保存会明确拒绝，不将缺失来源猜作基础父级；发布同一节点的新版本保持原父级。

个人派生节点保存在 SQLite，发布新版本使用 `expectedRevision` 乐观校验；已有版本仍可读取。拖入画布时创建新实例 ID，递归重映射内部节点、审核目标和输出投影，避免多个组合共用标识。实例 `origin` 固定自身派生记录的 ID、版本、名称、种类和基础类型，并以 `origin.parent` 保留该版本的直接父级。父级后续改名或更新不改变已有实例、运行和导出快照。

保存派生节点默认移除配置中的本机绝对路径及内嵌流程的输出根目录；业务代码、工具配置和固定 Skill 版本保留。业务代码与 Skill 要求的配置文件仍由输入契约及预检核对。内部模块、`preset`／`component` 种类、`/api/workflow-node-presets` 和存储表沿用兼容名称；这些名称不改变界面的“节点派生”语义。

## 组合与内部编辑

在画布中多选能力、数据、控制或人工节点，选择“封装为子流程”。系统根据选区的跨边界连线生成具名输入输出，允许修改端口显示名称；内部连接、类型和人工修改目标保留。外层是普通 subflow 节点，内部是普通工作流快照。

进入内部编辑使用独立暂存区。边界输入输出的身份、字段名和类型固定，内部能力与连线可以修改；应用后回写父流程，取消则恢复父流程原有历史和选择。内部编辑不创建独立看板条目、不保存成独立工作流，也不能启动运行、定时或学习。原有逐项和循环节点的固定内部快照也可进入编辑。

展开子流程时将内部能力映射回外层，并保留内部输出节点为阶段保存，避免丢失中间文件。外部人工审核修改目标重新定位到实际生产能力。工作流中的实例修改不会覆盖其来源派生版本，发布新版本需要显式操作。

## 明确限制及后续扩展

- 学习目标仍以外层节点 ID 和原业务范围绑定；指定工具和整个工作流学习不提供修改组合内部快照的授权。已绑定的 Skill／工具，以及正连接外部产物对比的能力，暂不直接封装；旧业务学习支线保留。组合内部学习需先有可版本化的内部路径及独立目标契约。
- 条件分支必须先在选区内汇总，不能把可能跳过的分支直接暴露成多个子流程输出；跨边界可跳过的可选输入同样明确拒绝。后续可增加显式“缺席值”传输协议，不能用 null 冒充未执行。
- 展开只支持能够映射到子流程最终输出的端口；额外字段投影会提示保留组合并进入内部编辑。逐项和循环保留控制语义，不提供直接展开。
- 执行中的子流程有原有父子运行记录及人工审核委托；本次不新增逐项并发实现，现有 foreach 仍按原顺序执行。独立分支的 DAG 并行保持。

这些限制在创建或展开时检查，不会等到消费模型额度后再静默改变行为。

新版可保留已填写的输入资料，但必须重新预检；运行记录、人工批准、会话和定时任务不随副本迁移。节点改动只改变工作流定义，不代表已经重新生成任何业务产物。普通副本入口见[另存为新版说明](workflow-versioning.md)，通过 AI 描述要求、审阅和应用修改的操作见[工作流对话](workflow-conversation.md)。
