# 测试固件开发

输入是工程事实 `boardFacts` 和测试要求；输出只给符合 [profile.schema.json](references/profile.schema.json) 的 JSON 配置。固定生成器负责从真实工程重新解析引脚、生成源码、编译并收集证据。

- target 采用真实芯片目标；双芯片模组分别识别主芯片与通信芯片。不能因已有工具链或复用3D模型改变目标。
- 从芯片识别、RGB、按键、复位、SD、USB console、摄像头识别、排针治具、MIPI DSI/CSI、C61链路和无线扫描中选择与实际电路对应的测试。没有外设时不借用案例引脚或测试项目。
- 摄像头型号必须来自明确测试要求或器件资料；`gc2145` 表示 SCCB 身份识别，不能宣称已验证成像质量。P4可选明确原厂软件测试配件profile：cameraSensor=sc2336、displayPanel=st7102-480x640；它们是测试配置而非从FPC推断的实物型号。没有已知型号用 null。
- fixturePairs 来自已核验网表的治具接线设计；可采用输入中明确标注的新设计，不能伪称已有治具。没有设计时保留空数组并报告缺口。生成器应报告配置待定，不能把未运行项目记为通过。
- 编译日志与 ELF/BIN 是构建证据，硬件测试必须由实板结果证明。执行不刷板、不复用案例 BIN 冒充新编译结果。
