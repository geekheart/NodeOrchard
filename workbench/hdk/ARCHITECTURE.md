# HDK 工程能力边界

工作流面向执行设计；学习是同一业务图的受控执行方式。共享调度器、人工审核与文件管理属于 `src/workflows/`，本目录只负责工程能力与固定校验。

## 小型 Skill 与固定工具

| 能力 | Skill 决策 | 固定工具负责 |
| --- | --- | --- |
| 导出与命名 | 明确目录、版本与发布策略 | 原生导出、当前源绑定、文件与哈希校验 |
| 工艺要求 | 依据当前板事实填写工艺决策与未决项 | 模板结构、控件／图片保留、定点写入与回读 |
| 测试固件 | 依据芯片、外设、引脚与目标设计 profile | 匹配 SDK、源码生成、真实编译和产物检查 |
| 测试说明 | 依据真实固件接口组织操作与判据 | 接线／文档生成、引用与来源验证 |
| Pinout／接口标注 | 依据当前事实设计标签与布局 | 原始照片、校准、真实工具渲染和产物核对 |
| 中英文指南 | 组织解释和操作步骤 | DrawIO、资源引用、双语一致性和交付检查 |

不把文件复制、哈希或 XML 单元格写入拆成模型调用。固件编译通过不代表硬件实测通过；图片自动检查不代替人工审核。

## 执行图与产物

新版 DAG 可以并行导出或生成互不依赖的资料；SOP 依赖真实固件接口，整包验收等待全部必要产物。图片由人工审核节点阻塞相关下游，阶段产物不必等到最终输出才保存。输入文件、原始工程、正反面照片、模板和参数在运行前预检，缺失时先报告。

权威原件保存在独立本机运行根，交付副本保存到指定目录。回执包含来源与哈希，能力只读取由控制器确认的同次运行、节点和版本。不能复用另一硬件的 Gerber、引脚、固件或验收记录充当新结果。

## 本地资料与公开源码

`hdk/*.json`、真实 `learning/` 数据与本机资料路径是私人配置，不随源码发布。公开资源目录只保留可共享的来源、身份与哈希；本机文件位置通过私有覆盖配置提供。维护中的 `skills/` 指令、固件资源和 schema 是源码。

自动化测试使用合成工程、OOXML、模板和图像证据。实际原生 EDA、转换器、SDK 和物理测试需要在本机准备，缺依赖时不能编造通过结果。

## 兼容与学习

`dag_capabilities.py` 是当前注册能力入口，按执行器提供的数据库、运行根和节点上下文验证。旧 pipeline／runtime 仍被部分能力复用，不能按名称批量删除；旧 schema1 的学习 gate 保持其原始来源与指纹要求，代码变化不自动更新放行证据。

学习支路明确选取对比产物与可修改 Skill，训练／验证遵守固定记忆隔离；执行模式跳过学习分支。候选只改授权正文，不改变事实、固定代码、样例或验收规则。参见[整体架构](../docs/architecture.md)及[学习契约边界](learning/README.md)。
