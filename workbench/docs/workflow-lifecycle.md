# 工作流回收站与删除

工作流按固定顺序管理：**工作流 → 回收站 → 永久删除**，也可以从回收站直接恢复到工作流。这些状态独立于执行/学习模式和运行状态。

| 当前区域 | 卡片「⋯」操作 | 结果 |
| --- | --- | --- |
| 工作流 | 移入回收站 | 进入回收站，停用关联定时任务 |
| 回收站 | 恢复到工作流 | 恢复为活动状态，明确打开后可编辑与运行；定时任务保持停用 |
| 回收站 | 永久删除工作流 | 输入完整名称后删除流程定义，不能恢复 |

节点编辑器只加载 `active` 工作流。当前工作流归档、移入回收站或永久删除后，立即卸载编辑器并清除当前选中指针，保留本地草稿、历史输入输出与产物。回收站记录不会作为只读流程留在节点编辑器中，编辑、保存、运行、学习、局部重跑和定时启用均被阻止。

无工作流 ID 的 `#/workflows` 在没有有效当前选择时显示空态，仅提供新建和返回看板入口，不自动跳转看板或选择其它工作流；仍有效的活动选择保留继续编辑行为，经明确 ID 重新打开和校验。旧归档／回收站直链和上次选中缓存都不能载入非活动记录。恢复只更新工作流库，用户明确打开后才重新读取服务端当前定义并加载；浏览器中的旧草稿不会自动覆盖它。

旧版本的 `archived` 工作流按 `trashed` 处理，统一显示在回收站，可直接恢复或永久删除；读取不会改写原有流程、聊天或历史记录。旧 `archive`／`unarchive` 操作分别兼容为移入回收站／恢复，旧 `archived` 列表参数兼容查询回收站。

永久删除保留历史运行、学习记录、反馈、暂停的定时快照和已生成文件，不做磁盘清理。历史快照和旧浏览器缓存不会使被删除的流程重新出现在看板。删除流程后，其关联定时任务不能直接重新启用。

流程仍有准备、排队、执行、学习或人工审核等待时，先完成或停止这些任务，才能移入回收站。界面提示和服务端都检查，异步文件预检、Skill 读取及定时触发期间也会在真正启动前再次核对状态。移入回收站与暂停关联定时任务在同一事务中完成，已经认领但尚未执行的定时触发也会取消。

每次管理操作都携带当前版本号，重复或过期请求会提示刷新；永久删除只能从回收站提交，并要求完整名称逐字匹配。菜单和弹窗支持键盘操作、取消、Esc 及焦点返回。

看板搜索仅作用于当前区域，数量显示当前命中数和区域总数。存在搜索或状态条件时，始终显示“清除筛选”，即使命中结果也能一键清空。看不到已有工作流时，先检查搜索词、状态筛选及当前区域。

## 验证范围

自动测试覆盖移入回收站、直接恢复、永久删除、旧归档兼容、应用重启后的持久化，以及编辑器卸载、无 ID 空态、旧直链／缓存、过期版本、等待审核和定时触发的状态检查。实际运行结果以当前测试输出为准；本机业务验收日志与截图保存在被忽略的工作环境中。
