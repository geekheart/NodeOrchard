# Skill 图片与外部工具

## 创建与运行

在 Skills 页或节点选择器点击“新建 Skill”，填写名称、描述、正文和工具依赖。图片模板使用 Hermes 原生 `image_generate`，不以本机画图代码替代模型出图。名称最多64个小写字母、数字或连字符；描述最多1024个字符且不超过2000字节，正文最多48000字节。

图像提供商与聊天主模型分别配置。用户手动选择图像服务后，只更新 Hermes 原生 `image_gen.provider`，认证继续由 Hermes 管理。已有 Codex 授权且原生图片插件可用时，可选择 `openai-codex`；实际是否成功仍以调用为准。提示词及参考资料会交给所选服务处理，并可能消耗额度。

创建后读回正文指纹，节点固定该版本；输出可选 `image`。按 **输入 → Skill → 人工审核 → 输出** 连接，生成后先保存、预览，用户审核后才交付。新建仅创建不存在的目录，不能覆盖已有 Skill，也不会自动运行其它工作流。

## 依赖与版本

Skill 前言用 `required-toolsets: ["image_gen"]` 声明依赖，节点保存 `requiredToolsets`。支持 `image_gen`、`browser`、`computer_use` 及已配置的 `mcp-*`；最多16项，去重检查并排序。声明只表达需求，不能安装工具、修改认证或授予权限。

目录区分真实可用与启用状态；缓存的工具名称不证明已就绪。浏览器必须有导航／执行工具，只有密码库工具不算就绪。可先保存尚未就绪的 Skill，但运行前拒绝缺失能力，不先消费模型调用。

每个实际尝试检查目录并绑定请求集合、工具名称和能力版本。版本摘要包含公开图片提供商／模型选择、工具状态及参数结构，不含凭据。准备回执须精确一致，重建与工具调用复核；人工重做遇到版本漂移时要求新建运行，不静默换提供商。旧 Skill 未声明依赖时保留原 Hermes 已启用工具，不自动增加工具；助手无工具、学习只读记忆与无工具声明继续生效。

## 图片与审核

原生图片工具没有工作台输出目录参数。网关只从成功工具回执读取真实 `cache/images` 图片，拒绝符号链接、硬链接和任意 URL 下载；校验后复制进该尝试会话目录。最多16张，单张25MiB，总计64MiB。

结束回执携带文件、哈希和工具身份。执行器不依赖最后一段文字，自行验证并归集、登记到节点产物目录；`sourcePath` 仅替换返回值中的旧路径，不授权读取其它文件。`image` 可绑定唯一真实图片，多图须明确选择；普通对象输出仍遵守原 JSON 契约，媒体不以 base64 塞入业务 JSON。

声明 `image_gen` 时静态预检要求 human 路径，自定义代码／Skill 实际产图后的动态审核检查也保留。schema1 无法表达此审核链，产图需升级 schema2。

## 软件接入

Figma 等软件复用 Hermes 已配置的 MCP，例如 `mcp-figma`，配置后工具及依赖动态进入目录。Codex 自己的插件连接不会自动成为 Hermes 连接；工作台不冒充已安装适配器，不自动添加服务器或输入凭据。

Computer Use 仍需 Hermes 原生驱动和系统权限；缺失时显示未就绪。声明 `computer_use` 的 Skill 在同一工作台执行器管理的工作流之间使用独立单槽串行；不锁住用户或其它程序的桌面操作。目标软件的认证和审批继续由 Hermes／软件管理。

新增适配复用目录、能力版本、尝试绑定、工具回执与产物机制，补真实依赖、目标／操作范围及必要的并发限制。未连接、仅协议回归通过和真实软件验收分别说明。

## 接口与人工入口

- `GET /api/skill-integrations`：无凭据的工具、图片提供商、采集时间及能力版本。短缓存合并重复读取，断连、重连及修改后失效。
- `POST /api/skills`：人工创建，传名称、描述、正文、`requiredToolsets` 和稳定 `operationId`。
- `POST /api/skill-integrations/image-provider`：人工选择，传 `provider`、`expectedProvider`、`operationId`，原生保存后读回。
- 助手用 `workbench.inspect(section="integrations")` 查询状态，`node.describe("skill")` 查询契约，没有创建或配置写工具。

写操作持久记录幂等回执；同内容重试读原结果，结果未知不自动重放。图片服务按原选择比较更新。日志只记录操作身份、状态、耗时和错误类型，不记录正文、图片提示词或认证。

Python 使用 `workbench.tools.catalog`、`workbench.skill.create`、`workbench.image.provider`，不向模型广告这些 RPC。Skill 准备仍走 `workbench.skill.prepare`，结束通过 `workbench.skill.finish` 返回可信产物。业务执行始终禁止 `skill_manage`；显式工具集绑定还禁止连接管理，旧工作流不擅自重写原生工具策略。

## 来源与删除

| 展示来源 | 判定及操作 |
| --- | --- |
| Hermes 自带 | 原生清单与实际目录确认；只读，不提供删除 |
| 工作台内置 | 仓库固定 Skill、完整匹配的已安装副本，以及固定内部助手指令；只读，不提供删除 |
| 后续创建 | 本版本创建时双端记录的生成身份，或数据库中的学习版本；可验证归属且没有在用引用时允许人工删除 |
| 其他来源 | 无法确认归属的旧本地包、外部安装包或不完整来源；受保护，不能仅凭 local、名字、前言或客户端传入来源获得删除资格 |

保留原 `source` 兼容执行与学习协议，另以 `origin` 提供可信来源和删除资格。旧版创建回执可能足够显示生成来源，但缺少本版本原生目录身份时仍保护。目录或包内容已变化、无法安全校验时也拒绝删除。目录展示不授予助手、工作流或包导入写权限。

`GET /api/skills?view=management` 和同参数详情提供管理目录，包括未安装的工作台模板及内部助手指令。它们使用固定命名空间、`assignable: false` 和明确用途，不混入默认节点目录。默认 `GET /api/skills` 继续只提供当前可用的工作流技能；内部助手工具及实验性权限仍沿原协议。

`POST /api/skills/:name/delete` 是 CSRF 保护的人工入口，仅接受 `expectedRevision`、`expectedCreationId`（学习版本为 `null`）与稳定 `operationId`。服务端重新读取来源、创建代次和版本，旧确认不升级为删除同名新包；再检查已保存工作流（含回收站）、嵌套子图、启用定时任务、在途运行／学习及派生版本；有引用则拒绝，不改引用流程。界面额外检查本窗口已知的未保存草稿，无法穷举其他窗口或应用外部的未保存内容。

新建原生包在独立私有记录中绑定 `creationId`、目录身份、正文版本及完整包指纹。删除再次验证这些身份，移动到 Hermes 忽略的 `.archive`，然后记录回执；不递归删除或改写历史。学习版本只做数据库删除标记，隐藏目录并拒绝新绑定，原始学习证据仍保留。删除与原生准备共用锁，活跃尝试期间拒绝移除。

同操作、同内容返回原回执，不用旧请求删除同名新包。明确的未修改拒绝可在移除引用后重新校验；已提交但结果未知的操作不自动重放。刷新失败时区分“已删除”与“结果未确认”。本机 macOS 已验证真实 Hermes 文件接口；安全锁与独占归档依赖 POSIX 能力，不支持的环境保持拒绝，不回退到宽泛递归删除。

助手用 `workbench.inspect(section="skills")` 读取有界来源元数据，不展开正文或学习证据。全局可执行资源删除保留人工入口，不作为模型工具开放。原生 `workbench.skills.catalog`／`workbench.skill.delete` 复用来源和受控记录；新增接口与来源规则同时维护能力目录、运行隔离及同接口回归。
