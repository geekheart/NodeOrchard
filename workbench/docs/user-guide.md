# 个人 AI 工作台

这是独立运行的本地应用。Multica 克隆保留在相邻的 `../multica/`，用于研究项目、任务、运行和 Agent 适配的设计。本工程使用自己的代码，第一版连接本机完整 Hermes 运行时。

默认首页为独立的**工作流看板**，参考 Multica 的列表与状态组织方式；原“工作台”首页已移除。全站共用左侧导航、中央主工作区与按需展开的执行详情面板。桌面端可手动折叠导航，选择在页面切换和刷新后保留；窄窗口默认显示图标栏，可展开完整导航，选页、Escape 或点击遮罩后收起。原“项目”页改为对话管理，Skills、统计和设置继续保留；任务详情内保留真实 Hermes 会话、流式消息、工具事件、审批、澄清、中断与恢复。

## 基础页面

- **工作流看板**：默认入口为 `#/board`，展示多个已保存工作流，支持搜索与打开编辑器。四列为“待完善 / 可运行 / 运行中 / 需处理”：依据图配置、真实执行和学习状态分组，不通过拖动卡片伪造运行状态。一次执行完成后，工作流仍是可继续使用的流程，不会永久归为“已完成”。看板集中展示待审批与补充信息请求，并提供进入关联任务处理的入口。
- **对话管理**：入口为 `#/conversations`，集中查看每条工作流的独立会话，以及按问题分开的总控主题。旧全局聊天和原普通任务历史继续可查；旧项目链接兼容进入此页。
- **工作流编辑器**：从看板打开某条工作流，进入 `#/workflows/:id`，手动编排 Skill / 工具 / 代码 / 子流程的并行依赖图；保留执行、学习、定时任务、导入导出与历史运行记录。旧schema1仍按原线性语义运行。
- **Skills**：从已连接的 Hermes 读取技能清单和原文详情，支持查找；当前为只读页面。
- **统计**：应用内最近 7 / 30 个 UTC 自然日的执行量与结果，读取本地 SQLite。未采集 Token、费用或订阅账户额度。
- **设置**：持久保存主题、列表密度和默认工作目录，展示模型连接及执行环境信息。顶部模型入口读取 Hermes 已配置的提供商与模型，并通过 Hermes 原生接口保存其全局默认选择；工作台不再保存本地模型覆盖。

核心业务功能将继续在这套页面框架上逐步定义。没有连接或没有数据时显示对应的空状态，不填充示例任务或虚构统计。

工作流文档以独立 ID 和版本号保存在本地 SQLite，可同时保留多个流程。每条文档有自己的浏览器缓存，切换流程不会共用同一份草稿；保存使用 `expectedRevision` 乐观锁（CAS），遇到其它窗口的新版本时保留本地内容并提示冲突，不静默覆盖。文档保存与执行、学习、定时任务各自的固定快照分开，修改文档不会改写已有运行或定时输入。

首次升级会从既有运行、学习和定时记录的原始快照补入文档库，不把未应用的学习候选当作已保存流程，也不覆盖已明确保存的文档。旧浏览器草稿单独迁移；打开每条工作流前也会检查其本地缓存，与已保存版本不同且无法确认来源时，保留为独立恢复副本。某条流程保存失败不会阻塞其它流程的打开与保存。旧链接 `#/workbench` 重定向到 `#/board`。任务详情与原项目中的任务历史继续从对话管理页的历史任务入口查看。

## 对话管理

每条工作流只有自己的独立会话入口；从管理页打开后继续使用已有记录。工作流之间的聊天不会自动合并，总控主题也不会成为工作流消息。尚无聊天记录的流程显示空状态，不会为了填满目录而生成示例消息。

跨工作流问题可以新建一个总控主题。总控先看目录摘要，再按需读取具体会话；需要目标助手检查时，只委派只读诊断并保留任务状态。诊断提交、助手回复完成和实际修复分别显示；节点修改仍通过候选、人工应用和独立运行验证处理。总控不会因为读取会话而批准审核、启动运行或结束其它聊天事项。

原来全站共享的总控聊天作为历史入口保留，原普通 Hermes 任务仍可在历史任务中打开。看板、Skills、统计和设置不再显示同一总控聊天；处理工作流时使用其独立会话，处理跨流程问题时回到对话管理。权限不足时到“设置 → 助手权限”调整，AI 无权更改这些设置。

## 工作流编辑器

从工作流看板新建或打开流程，进入该文档的 `#/workflows/:id`。这是手动编辑器：从节点库拖入节点，通过端口连接，在属性栏编辑名称和配置。连线会检查端口类型与方向，工作流整体遵循 DAG 约束；循环由循环节点表达。

新建默认使用 **schema2**；旧文档可显式升级。新版区分“编辑/运行”视图与“执行/学习”方式，具名端口支持多输入输出、并行分支、汇合、多个任务排队、资源限额、子流程及有界逐项/循环。文件、文件夹、图片与参数统一在“输入资料”准备，手动和定时共用预检。

图片生成后立即保存并预览，经人工审核才能进入相关后续能力。审核支持通过、反馈修订、停止；局部重跑保留无关分支，历史尝试可在节点详情回看。中途输出也可保存TXT/JSON并继续传递。产物采用每运行/节点/尝试独立目录，执行原件与用户输出目录中的交付副本分开保存；审核等待可持久恢复，在途结果不明则标未知。学习等待恢复使用原批次只读memory快照。

操作与边界见 [新版编辑器使用说明](workflow-editor-v2.md)、[输入及恢复机制](workflow-inputs-and-recovery.md)。个人验证记录仅保留在本地忽略目录；引擎已支持并行不代表任意旧专业流程都已迁移。

节点库、属性栏和工具栏复用工作台的主题、文字、表单与按钮样式，支持浅色、暗色及跟随系统。节点、端口和连线保留分类配色；窄窗口的工具栏自动换行，节点库与属性栏作为可收起的抽屉显示。

窄窗口将新建、导入、导出与保存显示为带名称提示的图标按钮；底部面板为画布工具与缩放控件预留高度，长结果和样例表格在各自区域内滚动。抽屉遮住大部分画布时不会为了避让而把节点移出视野。运行面板底部保留“添加 Skill / 添加工具 / 代码 / 创建最小流程”快捷操作，折叠后只显示运行摘要。按钮可用空格键操作，学习样例详情进入及返回时保持可用的键盘焦点。

画布背景使用全站背景色，点阵由中性边框色轻量混合生成，随缩放和平移保持对齐。普通连线与键盘焦点采用全站灰色及强调色；节点底色、分类边框、端口、关联连线配色和接线确认动效保留。

底部运行面板优先展示有序节点、状态及所选节点的实际输入 / 输出，能力版本、运行时间和代码日志可展开查看；下次运行输入与历史实际输入分开展示。学习面板优先展示已有结果，包括轮次、全部 / 训练 / 验证通过率、逐例得分和 I/O、Skill 修改前后对比；下次学习配置保留在结果下方。两种面板按中央区域的实际宽度调整布局，历史、停止、复制下载、样例编辑和候选应用操作保持可用。

编辑器支持撤销 / 重做、画布缩放和平移，以及 JSON 导入 / 导出。已提交的草稿自动写入本条浏览器缓存并同步到 SQLite 文档库，顶部显示同步或冲突状态。连接同一个本地服务的其它浏览器可打开已保存文档；尚未确认同步的内容仍需保留本地缓存。JSON 导出用于独立备份与跨主机迁移，清除浏览器站点数据不会删除已保存的 SQLite 文档。

节点库包含输入 / 触发、输出、Skill、工具 / 代码、子流程、数据整理、汇总、条件判断、逐项处理、条件循环、人工审核以及学习对比/改进节点。支持搜索、右键添加、多选、复制及键盘微调。属性需要点击“应用更改”或使用保存操作后进入草稿，尚未应用的字段会在顶部提示。JSON 文件上限为 2 MB。

`examples/document-review.workflow.json` 提供六节点的分支编辑示例，可通过“导入”载入；Skill 名称和版本仅用于演示引用格式。循环节点第一版保存循环体的子流程引用与次数上限，暂不支持展开编辑内嵌子图。

`examples/humanizer.workflow.json` 是已通过真实订阅验收的三节点流程。导入后可直接选择 `humanizer` 并输入文字；若本机 Skill 内容已更新，请在属性中更新内容指纹。

旧schema1执行模式支持**一个手动输入 → 一个或多个 Skill / 工具 / 代码能力 → 一个输出**，所有节点和连线必须恰好组成一条线性链；schema2改为按真实依赖调度并行图。执行顺序取决于连线，不取决于节点在 JSON 中的排列或画布位置。点击底部“创建最小流程”可继续使用三节点示例；选中输入或任意能力后点击“添加 Skill”或“添加工具 / 代码”，会自动插入并重新接线，也可撤销。Skill 在属性中选择 Hermes 已安装技能；工具 / 代码节点明确选择内置工具或代码模式，切换为工具模式后不会执行隐藏的代码。

`examples/multi-skill.workflow.json` 保留通过真实订阅验收的 `humanizer → meeting-action-items` 串联示例。`examples/mixed-capabilities.workflow.json` 展示 `trim → humanizer → JavaScript 对象 → json.stringify → Python 文本 → meeting-action-items` 混合链；`examples/local-data.workflow.json` 展示无需连接 Hermes 的本地 JSON 处理。导入包含 Skill 的示例后，若本机技能内容已更新，请更新内容指纹。

运行前会应用待保存属性，校验整条链、代码 / 工具配置及所有 Skill 的名称和正文指纹；任一配置或引用失效时，不创建运行记录、会话或模型调用。包含 Skill 时，为每个 Skill 创建独立 Hermes 会话，**先完成所有 Skill 的完整目录副本准备，再开始任何节点执行**，包括排列在 Skill 前面的本地代码。之后修改画布只影响下一次运行。

支持文本和 JSON 对象 / 数组 / 数字 / 布尔值输入；每个输入、节点结果及交接值，完整 JSON 的 UTF-8 序列化大小均不能超过 64 KiB，较大文件通过产物引用传递。Skill 输出类型为 `text` 时保留正文，结构化类型要求模型返回严格匹配的 JSON；`any` 尝试解析 JSON，不能解析时保留文本。交接保留原有类型并校验下一步端口。schema2已接通本机文件选择、分支、循环和子流程；自动重试仍不执行。

### 定时执行

在工作流顶部点击“定时任务”，可按指定日期时间执行一次，或每天在固定时间执行。选择 IANA 时区（默认沿用入口配置，如 `Asia/Shanghai`），填写固定运行输入并保存；文本与 JSON 格式明确区分，支持 `0`、`false` 和非必填的 `null`。任务保存当前执行模式草稿及输入的固定快照；后续编辑画布或更新 Skill 不会自动改变已发布任务。编辑任务时明确采用当前草稿重新保存，Skill 来源指纹变化仍按原执行校验拒绝运行。入口节点的每日时间只是新建任务的默认值，不会因修改属性自动发布定时任务。

任务保存在工作台 SQLite，支持查看下次时间、暂停、恢复、编辑及删除。单次触发后自动结束，需修改为未来时间才可再次启用；每日任务计算下一次本地时间，夏令时缺失的时刻跳过，重复的时刻只执行第一次。最近触发状态可区分执行完成、离线、忙碌、错过或失败，“查看运行结果”沿用逐节点输入 / 输出与状态面板，运行记录标明定时来源。

工作台服务必须运行，电脑须保持唤醒；关闭浏览器页面不影响调度。正常轮询延迟在 1 分钟内允许启动；迟到超过 1 分钟或服务重启时已经到期的任务记为错过，不补跑。含 Skill 的任务到点需 Hermes 已连接，所选提供商与模型在 Hermes 中配置可用；离线不自动连接，审批仍需按原有机制处理。每次触发创建运行时固定当时的主提供商与模型。同一工作流执行 / 学习忙碌时跳过该次触发并记录原因，不自动重试。暂停或删除取消后续触发及尚未创建运行的准备过程，已开始的运行和历史保留，需在运行面板另行停止。学习模式只允许查看管理既有任务，不创建或恢复调度；最多保存 100 个任务。

内置工具来自共享的固定白名单：

| ID | 操作 | 输入 → 输出 |
| --- | --- | --- |
| `text.trim` | 去除首尾空白 | text → text |
| `text.uppercase` | 转换大写 | text → text |
| `json.parse` | 解析 JSON 文本 | text → any |
| `json.stringify` | 生成 JSON 文本 | any → text |
| `json.keys` | 读取对象字段名 | object → array |

另已注册七个`hdk.four.*`专业能力，覆盖资料核验、原生SCH/STEP、CAD、Pinout事实与正反面出图、汇总验收。它们通过来源绑定回执交接，不依赖旧流水线共享阶段文件；专业业务迁移状态以重构记录为准。

本版不会把 Hermes / MCP 展示清单中的任意工具名称直接当作可执行节点；工具模式仅调用已注册实现。

代码模式填写函数体，`input` 是上一步的真实结果，`return` 是本步输出。JavaScript 在 async 函数体中执行，可使用 `await`；Python 填写同步 `def main(input)` 的函数体，不再包一层函数定义。例如，两种语言均可用 `return input` 原样传递数据。`console.log` / `print` 等标准输出与错误输出分别记入节点的 `stdout` / `stderr`，每路最多 32 KiB，截断会显示标记；日志不作为返回结果。

代码运行在本机独立进程，使用配置的工作区、最小继承环境，并支持超时及停止时终止进程。这适合可信本地代码，不是 OS 沙箱；用户代码调用外部工具产生的副作用由该代码承担，停止不会撤销它们。纯本地工具 / 代码链无需 Hermes 连接或模型认证；Skill 节点经 Hermes 执行。

节点准备与输入绑定分开：后续 Skill 可先用空占位完成快照准备，轮到该节点时，再从同一个固定副本绑定上一步结果。它不会在执行到第二步时重新读取当前 Skill 来替换本次版本。

每次工作流运行固定一次 Hermes 主提供商与模型，所有 Skill 节点、后续修改尝试和子流程沿用该选择。模型认证、端点及回退配置由 Hermes 管理。运行面板显示各节点自己的输入、输出、流式预览、状态、时间、执行信息和日志；有 Hermes 会话的节点提供关联任务链接，本地工具 / 代码节点不伪造会话。Skill 必须收到 Hermes 成功终态、读回持久历史中的最终助手结果，并通过完整性校验；本地节点必须完成工具调用或代码进程并验证返回值，才将结果传给下一步。只有全部能力节点成功才确认最终输出。下游失败或停止时，保留上游已完成结果，未执行节点标为“已跳过”。

切换 Hermes 默认模型只影响之后创建的会话、工作流运行和学习批次，不改写已有会话或在途运行。恢复旧记录时优先使用已保存的主提供商与模型；旧工作流运行或学习批次可从关联会话确认唯一选择时补回，否则拒绝继续模型步骤并保留现有产物。未记录模型的旧空会话无法安全重建，需要新建任务。

Skill 的审批 / 澄清会汇总到看板的待处理区域，可进入关联任务处理；节点的“查看关联任务”也保留。停止等待后端确认；本地代码停止记为已停止、超时记为失败，Skill 中断未获确认或断线保留待核对状态。纯本地链不受 Hermes 断线影响。重启不重放在途能力；schema2可恢复纯人工等待和排队，含Skill的队列等待完整模型就绪。旧schema1同流程单运行；schema2允许多个运行排队并按全局准入限额推进。

普通执行模式的会话关闭 Skill 总结与 `skill_manage`，保留 Hermes 原有 memory 读取与更新机制。技能资源从固定副本加载，前后校验源目录与副本；普通文件 / 终端工具仍使用 Hermes 自身审批。这是固定副本和完整性审计，并非操作系统文件沙箱。学习模式另使用下面的整批只读记忆策略。

运行记录、流程与 Skill 元数据快照、逐节点 I/O、`logs` 和 `runtime` 保存在本地 SQLite。`runtime` 记录实际能力类型、语言或工具名称及 `revision`。Skill 正文审计记录位于数据目录的 `workflow-snapshots/`，固定副本位于节点会话目录的 `.workbench-skills/`。选择运行及节点版本可重新查看。schema2输出节点和产物能力实际保存文件；浏览器“下载”另存副本。工作流关联会话保留历史、审批和停止，固定会话的重新执行从工作流页面发起。

新建 schema2 运行的执行原件默认放在本机应用数据目录：macOS 为 `~/Library/Application Support/PersonalAgentWorkbench/runs/`，Windows 为 `%LOCALAPPDATA%/PersonalAgentWorkbench/runs/`，Linux 为 `${XDG_STATE_HOME:-~/.local/state}/personal-agent-workbench/runs/`。节点交接、预览、SHA 校验和人工审核均引用原件。运行完成后，将交付副本保存到工作流配置的“输出根目录”；留空仍使用工作区的默认 `outputs/`。这样自定义输出目录或同步目录中的副本变化不会破坏运行引用。运行页分别显示执行原件目录与交付副本目录，并提供“打开执行原件目录”。

交付副本只包含已完成输出节点明确声明的文件、资料包和自身保存的结果，包括中途的阶段输出。资料包按已登记清单携带正文、图片和附件，成员逐项校验；节点继承的上游产物列表用于预览和核验，不会把所有依赖目录与历史尝试一起复制。需要交付某份成果时，将它明确连接至输出节点；原件目录仍保留完整执行资料。

交付副本保存失败会单独显示错误，执行原件与已完成节点保持原样。可点击“重试保存交付副本”重新保存；副本之后被删改时，可用“检查并补齐交付副本”。这些操作不重新执行节点、调用模型或要求再次审核，变化的内容发布到新交付修订，不覆盖已有副本。旧运行按原目录继续读取，不批量迁移或改写历史回执。`WORKBENCH_RUN_ROOT` 可显式指定执行原件根目录；使用自定义 `WORKBENCH_DATA_DIR` 或 `WORKBENCH_WORKSPACE_ROOT` 的隔离环境会自动派生该环境内的运行目录，避免测试写入真实用户目录。

“减少动效”只调整连线和界面的视觉效果，不会暂停或取消后台任务。

## epro2 四文件生成

独立四文件工作流从同一输入原生导出 SCH PDF 与 STEP，使用 OpenStep2DWG 生成二维 DWG，再从实际 PAD_NET、原生编号焊盘和已校准的正反面实拍图生成 OpenPinMap 引脚图。四项成果按案例命名，另保留可编辑项目、回读报告和源哈希；不复用旧案例引脚或模型。使用方式、依赖准备与准确边界见 [四文件工作流](four-files-workflow.md)。

## 运行结果综合反馈

在最终结果旁点击“在对话中反馈”，或直接回复右侧对话，描述本次产物的问题和期望。普通反馈绑定对应运行、节点尝试和产物；只有一份合格结果时可自动关联，存在歧义则在对话中选择。保存反馈不需要连接 Hermes，也不会自动训练。原有综合反馈表单仅作为没有对话入口时的兼容路径；历史分项反馈继续可读取。

希望以后沿用时，在同一对话中说明“以后都按这个规则”及具体 Skill，确认“生成可复用规则候选”。缺少改进范围时，对话先提出仅包含明确目标的配置，应用并运行后再基于新的执行快照学习；不会改写旧运行。模型结合目标 Skill 的实际输入、输出和后继生产节点结果，在 Hermes 固定只读记忆快照下生成候选。工具、代码、frontmatter、其它 Skill 和原产物保持原样，生产流程不会自动重跑。学习面板可检查反馈、依据和正文差异；候选仍需验证，不生成虚构的分数或通过率。

“应用候选到草稿（未验证）”是手动、可撤销的引用替换。应用时再次核对反馈版本、原 Skill、候选指纹和当前草稿；之后仍需独立样例验证与用户复评，已有的工程验收和执行门槛继续生效。普通执行的 Hermes memory 更新机制保持原样。

## 学习模式

切换“学习”，维护训练集和验证集，再设置评价标准、可训练 Skill、目标分数与最多总轮数。默认 3 轮、上限 10 轮，均包含第一轮基线。两组合计最多 20 条样例，至少有一条训练样例；没有验证集时明确显示“未验证”。可逐条添加、编辑、移动分组或删除，也可用文件或粘贴方式批量导入 JSON、JSONL、CSV，先预览再确认添加或替换。解析失败不会覆盖已有样例，相同输入、冲突答案及跨组重复会被拒绝。每个输入 / 答案最多 64 KiB，数据集合计最多 256 KiB（UTF-8 JSON）。

JSON 支持 `{ "trainingCases": [{ "input": "输入", "expected": "答案" }], "validationCases": [] }`，也支持带 `split: "train" | "validation"` 的平铺数组；JSONL 每行一个平铺样例。CSV 必需表头为 `input,expected`，可增加 `split,id,name,input_format,expected_format`。CSV 默认保留文本，只有显式指定 `json` 格式才解析对象、数字、布尔值等；不会把文本 `false` 或 `0` 自动变成 JSON。样例可提供稳定 `id` 和名称，未提供时自动生成。模板见 `examples/multi-example-learning.dataset.json`、同名 `.jsonl` 和 `.csv`。

学习执行完整混合流程，每轮重跑全部训练和验证样例，保留逐节点输入 / 输出、状态和日志。图结构、工具与代码配置保持固定，每次调整一个勾选的 Skill。页面显示本轮与最多完整流程执行次数；模型评价、改写及大上下文诊断会额外调用模型。尚未启动的配置只在当前页面保留；启动后冻结在学习记录内，刷新可恢复或点击“使用此记录配置”。

学习循环为 **基线执行 → 对比答案 → 生成候选正文 → 重跑全部样例**。精确对比规范文本换行和首尾空白，JSON 深比较忽略对象键顺序；AI 评价逐例比较完整已知答案与结果，给出 0–100 分及理由，属于模型估计。每轮显示逐例状态、得分和是否通过，以及总体 / 训练集 / 验证集的通过率、平均分和最低分。分母包含尚未运行的样例，未完成评分时显示待评数量；全部样例完成且达到目标才结束。

改写使用全部训练样例的输入、答案、最佳与最近结果；大上下文先逐例诊断再汇总，不静默截断或跳过样例。验证样例和反馈不直接提供给改写模型。最佳版本先比较训练与验证两组中较低的通过率，再比较总体通过率、最低分及平均分；达到上限或没有有效新修改时保留最佳已验证版本。验证集用于选择版本和回归检查，并非从未参与选择的最终测试集，不能据此保证对所有输入有效。

每个新学习批次在基线前固定一次 Hermes 内置记忆快照；全部训练 / 验证 Skill，以及评分、诊断和改写会话共享这份只读快照。确认成功前不运行样例或发送学习模型提示。批次内不更新内置记忆，也禁用外部记忆的动态检索与写回；快照正文只留在 Hermes gateway 进程，不复制到 SQLite 或浏览器。普通执行模式继续按原设置读取和更新 Hermes memory。

学习记录的 `memoryPolicy` 区分准备中的 `pending`、已确认的 `batch-snapshot` 和旧记录的 `legacy`；只保存策略与 scope ID。旧批次未实现整批记忆隔离，不能因页面升级将其视为已隔离。学习 scope 未知或已释放时直接拒绝，不回退实时记忆。停止、结束或关闭会释放 scope，迟到返回也会清理；重启不会重建快照或重放学习。

候选只改 `SKILL.md` 指令正文，保留原 frontmatter 元配置与其它资源。工作台在本地 SQLite 保存独立的 `wb-learn-…` 引用和正文指纹；Hermes 运行时仍从原 Skill 复制完整资源包，再仅替换本次固定副本的正文，分别审计源包与候选副本。原 Hermes Skill 文件不被覆盖。学习批次在准备记忆快照前固定主提供商与模型，样例执行、评价、诊断和改写沿用该选择；控制调用使用独立无工具会话，并使用同批记忆快照。

学习 scope 的 Skill 会话禁用原生 memory 工具、外部记忆 provider，以及可能脱离 scope 的 `delegate_task`、`cronjob_manage`、`message_agent` 和 `kanban_*` 工具；普通执行模式不增加这些限制。学习 Skill 的其它文件 / 终端工具仍使用 Hermes 审批，本地代码仍在可信宿主执行。这份记忆策略不构成 OS 沙箱，也不隔离任意文件、网络或代码副作用；快照中的既有记忆可能已包含相关事实。验证集仍参与版本选择，严格独立评估需要另留最终测试集。

每轮可查看实际结果 / 已知答案、评分 / 反馈、Skill 修改前后全文，以及该样例的节点执行详情。结束后点击“应用最佳候选到草稿”，将已验证的 Skill 引用和指纹写回原流程并切到执行模式；这是一次可撤销的草稿操作。后续普通执行保持该版本固定。应用前后都会核对原 Skill 版本，来源变更时要求重新学习。候选在应用前不会出现在普通 Skill 选择列表中。

每轮会重复运行全部工具和代码，停止不会撤销已经发生的副作用。停止、断线或关闭后不再调度新轮次；应用重启保留记录并标为待核对，不自动恢复或重放学习。一个工作流的学习批次与普通执行互斥。学习次数上限控制迭代数量，不等同于订阅费用或 Token 预算。

`examples/learning-text.workflow.json` 是基于 `humanizer` 的学习示例；`examples/learning-text.config.json` 提供小写转换的输入、答案、规则和独立验证短语。它们展示配置方式，不安装或覆盖 Hermes Skill。

连线只有建立成功时播放一次确认动效；悬停高亮关联线，分类配色保持不变。节点角标显示后端确认的运行状态，不以连线动画模拟运行。

## 启动

需要 Node.js 22.13 或更高版本，无需安装 npm 依赖。本地内置工具与 JavaScript 代码可直接运行；Python 代码需要可用的 Python 解释器，当前使用 `WORKBENCH_HERMES_PYTHON` 配置。

使用 Skill 或聊天任务前，必须先独立安装、配置并验证 Hermes。本应用不会安装 Hermes。请按 [Hermes 官方安装文档](https://hermes-agent.nousresearch.com/docs/getting-started/installation/)完成安装；macOS / Linux / WSL2 的官方源码安装入口为：

```sh
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

重新加载终端环境后，先运行 `hermes model` 选择提供商与模型，并在 Hermes 内完成所需认证，再运行 `hermes` 验证一次正常对话。使用 ChatGPT 订阅时可选择 **ChatGPT or Codex Subscription**；也可使用 Hermes 支持的其它已配置提供商。完整配置步骤见 [官方快速开始](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart/)。不要把令牌、密码或 API key 填入工作台诊断页。

当前已核验 Hermes 0.21.4 的 gateway 与模型选择接口；这不代表所有版本均已验证。工作台默认读取 `~/.hermes/hermes-agent` 的源码及其中 `venv/bin/python`。自定义安装、Hermes Desktop 打包运行时或其它布局须按实际路径设置下方的 `WORKBENCH_HERMES_ROOT`、`WORKBENCH_HERMES_PYTHON` 和 `WORKBENCH_HERMES_HOME`，并确认所需接口兼容。随后启动工作台：

```sh
cd workbench
npm start
```

打开 <http://127.0.0.1:4318>，默认进入工作流看板。纯本地流程可直接执行；需要 Skill 或聊天任务时点击“连接后端”。顶部模型入口会读取 Hermes 当前选择和已配置提供商，仅允许 Hermes 明确确认已认证的提供商提交切换。可选择建议模型或输入模型 ID；最终必须由 Hermes 原生选择接口确认、保存并严格读回后才显示成功。涉及费用或数据策略等选择提示时，需要先在 Hermes 原生界面完成确认，再回工作台刷新。Hermes 审批模式必须为 `manual` 或 `smart`。

## 验证

默认测试不读取真实账号或调用模型；代码执行测试会启动隔离数据下的本地 worker：

```sh
npm test
python3 -B -m unittest discover -s test -p 'workflow_gateway_test.py'
```

自动化测试使用隔离数据、合成 fixture 和真实本地 worker，不调用真实模型；实际结果以当前测试输出为准。个人验收日志和截图保存在忽略目录，不随源码发布。

明确授权后的真实验收会消耗所选模型的额度或产生费用，并在测试工作区写入一个随机标记文件。当前 `smoke` 脚本仍限定 `openai-codex` 订阅路由；这只是该专项脚本的限制。先在 Hermes 中配置相应路由并启动应用，再运行：

```sh
WORKBENCH_RUN_REAL_SMOKE=1 npm run smoke
```

真实验收报告保存到 `.local/smoke-report.json`，生成文件位于 `workflow/artifacts/architecture-smoke.txt`。只有收到最终成功事件、读回内容一致且 Hermes 历史可查，验收才通过。

多 Skill 专项验收使用真实 Hermes 模型调用，验证 `humanizer → meeting-action-items` 的确切数据交接、串行时间、独立会话和 Hermes 最终历史。显式运行 `WORKBENCH_RUN_REAL_SMOKE=1 node scripts/workflow-chain-smoke.mjs`；报告保存到 `.local/workflow-chain-smoke-report.json`。脚本不会自动批准工具请求或重试失败运行。

## 配置

可通过环境变量配置，应用不生成或复制 Hermes 认证文件。

| 变量 | 默认 |
| --- | --- |
| `WORKBENCH_PORT` | `4318`，只绑定 `127.0.0.1` |
| `WORKBENCH_HERMES_ROOT` | `~/.hermes/hermes-agent` |
| `WORKBENCH_HERMES_PYTHON` | Hermes 自己的 `venv/bin/python` |
| `WORKBENCH_HERMES_HOME` | `~/.hermes` |
| `WORKBENCH_DATA_DIR` | `.local/` |
| `WORKBENCH_WORKSPACE_ROOT` | 项目根目录 `workflow/` |
| `WORKBENCH_RUN_ROOT` | 本机应用数据目录中的 `PersonalAgentWorkbench/runs/`；显式设置数据目录时为其 `workflow-runs/`，只设置工作区时为其 `.workbench-runs/` |

会话和代码的工作目录必须位于配置的工作区内。该目录检查用于管理工程位置，不是操作系统沙箱；Hermes 工具服从其运行环境及审批配置，本地代码以工作台进程用户的权限运行。

模型配置由 Hermes 统一管理。`WORKBENCH_HERMES_MODEL` 不再读取；旧偏好中的 `defaultModel` 也不会覆盖 Hermes 默认选择。gateway 启动时会移除继承的 `HERMES_MODEL`、`HERMES_INFERENCE_MODEL`、`HERMES_TUI_PROVIDER` 和 `HERMES_INFERENCE_PROVIDER`，避免环境覆盖已保存的选择。
