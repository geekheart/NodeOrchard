# 应用助手能力维护与扩展

本页用于新增功能、改变节点／执行接口、增加诊断工具、扩展内部 Skill 或接入 MCP 时同步维护助手能力。目标是让助手能主动发现真实接口，并按相同校验提出或执行获准操作。能力说明不替代实现，工具存在不代表前置条件已经满足。

## 权威来源

| 层 | 权威内容 | 维护要求 |
| --- | --- | --- |
| `shared/workflow/workflow-capability-contract.mjs` | 浏览器与后端共用的能力身份、边界及节点契约 | 保持纯模型，不读取本机文件、依赖、认证或数据库 |
| `src/application-capabilities.mjs` | 当前应用的能力目录、节点说明及可用性投影 | 从真实共享模型及处理器派生，区分产品支持与本机就绪状态 |
| 会话权限模块及人工权限设置 | 服务端角色、工具准入、对象归属与工作目录边界 | 身份由对话入口绑定；配置由设置页提交，模型参数与提示词不能提升权限 |
| 应用工具的 schema 和 dispatcher | 工具名称、参数与真正的调用权限 | 每个已广告工具有对应处理器；未知工具和多余参数明确拒绝 |
| `src/assistant-diagnostic-turn.mjs` 与对话持久化模块 | 紧凑上下文、阶段、检查点与证据有效期 | 保留对象身份和省略标记；复用不扩权，失败与重启不重放 |
| `src/application-conversation-hub.mjs` 与工作流／总控会话存储 | 会话目录、主题隔离、历史读取与只读委派 | 先读摘要再按需展开，消息和操作始终绑定目标会话，旧记录保留 |
| `src/application-assistant-skills.mjs` 与 `assistant-skills/` | 内部 Skill 的固定目录及如何组合、选择和解释已有接口 | 由注册表发现并按需读取，不扫描用户业务 Skill，不把说明文字视为新增工具授权 |
| 节点规划、执行、文件与审核模块 | 实际参数、类型、产物和状态语义 | 接口变更同时回写能力契约及相关说明 |

内部助手先使用 `app.capabilities` 获取能力范围，配置节点前按需调用 `node.describe`，检查解释器／执行环境时使用 `runtime.inspect`。具体参数、返回字段和可调用的内部 Skill 以当前工具目录及 schema 为准；本页不复制可执行 schema。

例如，工具与代码节点的 Python 函数体、`input`／`context`、输出 JSON、文件产物目录和依赖条件应能通过能力说明取得。不能因为注册工具目录没有 XLSX 导出器，就断言已有 Python 代码节点也不能产生工作簿；也不能因为执行器支持 Python，就承诺第三方包已安装或节点可以保持原 ID 换型。

运行时合约按语言说明字段访问：schema2 文件目录分别为 JavaScript 的 `context.outputDirectory` 和 Python 的 `context['outputDirectory']`。Python 上下文是普通 `dict`；JSON 对象输入解码为 `dict`、数组为 `list`，须检查输入形状并用方括号或 `dict.get` 读取对象字段。规划提示与 `node.describe` 共用这份真实合约，不把 JavaScript 的属性访问写法套用到 Python。

## 能力状态

新增可由代码完成的用户操作，应同步提供或扩展受控助手工具。人工审核、认证等确需用户处理的入口保留明确原因；不能只把新功能列入目录，就声称助手已经能操作。

| 状态 | 含义 | 助手应如何处理 |
| --- | --- | --- |
| `available` | 当前接口允许调用该能力，实际依赖和对象范围已声明 | 检查所需运行时条件，再通过对应工具调用并核对结果 |
| `proposal-only` | 可以生成可审阅候选，不能由这项能力直接执行业务 | 展示修改范围、候选与应用入口；应用和运行分别报告 |
| `ui-only` | 产品界面支持，但当前助手没有相应受控操作接口 | 说明界面入口或明确接口缺口；不虚构工具调用 |
| `unavailable` | 处理器未实现、依赖不满足或当前对象不支持 | 返回具体原因与所缺条件，不声称已经执行或验证 |

产品能力和运行时状态分别判断。已注册代码节点不等于某个 Python 包可导入；模型目录可读不等于账号已认证；预检通过不等于文件已经生成；隔离浏览器截图不等于用户当前标签页截图。运行时不应只依据提示词或旧文档推断就绪。

## 会话权限与人工设置

独立会话由服务端绑定当前工作流，总控会话取得单独的服务端身份。模型只能选择该身份实际广告的工具；dispatcher 在读取和执行前重新校验配置与对象归属。省略目标时使用当前工作流，显式传入其它工作流、运行、会话或产物的 ID 不能越过归属检查。权限变化后，旧工具目录、诊断检查点和重试内容不构成继续访问的授权。

| 身份 | 可分配能力 | 固定边界 |
| --- | --- | --- |
| 独立工作流助手 | 读取当前工作流和运行日志；提出工作流／节点修改；派生业务代码节点；读取工作资料；受控截图与短录制 | 当前工作流与服务端绑定的工作文件夹，不取得其它工作流、全局软件日志或流程管理权限 |
| 总控助手 | 以上能力，以及跨工作流读取、复制、创建测试工作流、移入回收站和读取软件日志 | 仅通过目录中的受控接口；流程删除保留恢复途径，创建与复制不自动运行 |

设置页的“助手权限”分别控制两种身份的能力。用户通过设置表单修改，保存需当前权限版本；版本变化时保留未保存选择并提示重新读取。任何助手均没有修改权限设置的工具；模型输出、浏览器诊断代理或未来 MCP 适配器不能取得该入口。此保护约束应用助手接口，不能替代任意业务代码执行所需的操作系统隔离。总控身份不等于软件管理员 shell 权限，双方都没有工作台源码写入和任意本机文件工具。

总控管理入口为 `workflow.copy`、`workflow.create-test` 和 `workflow.delete`：写入使用稳定操作 ID 及预期修订，重复同内容读回原回执，不同内容复用 ID 明确拒绝；未确定结果保持未知，不自动重放。删除直接移入可恢复回收站，并在同一事务内暂停定时任务；恢复由界面直接返回活动工作流，定时任务保持暂停。助手没有永久删除接口。复制保留业务节点但清空交付目录，不复制运行、聊天和定时任务；测试流程带明确测试名称，两者均不启动运行。`app.logs` 按等级、模块、时间及关联ID读取有界持久元数据，支持跨启动分页；当前进程Hermes窗口单独标识。不接受任意路径或日志写入，详见[应用日志](application-logging.md)。

管理权限不是任意轮次的修改授权。服务端从本轮人工消息核对管理动作与目标；只读诊断、保留现场、否定或引用中的命令不能授权写入，不明确时提示用户明确请求。操作 ID 由服务端按消息及操作内容绑定，模型更换 ID 不能重复创建；回执身份单独持久保留，不作为可重放缓存。

独立会话应用修改前先通过只读权限与候选指纹校验，撤销权限后的旧建议不会先改画布再报错。业务代码、表达式、嵌入子流程及工作流引用也接受相同范围校验。

当前工作文件夹由服务端工作区配置和人工设置的默认工作目录解析；相对路径以工作区根目录为基准。`document.settings.outputDirectory` 是业务交付位置，不是助手目录授权。目录判断校验真实位置和符号链接，不能用 `..`、输出目录变更或产物路径扩大范围。受限助手可以读取有归属的运行记录，但目录外文件内容仍按工具的目录边界拒绝。

这些限制作用于助手接口；可信业务代码候选仍由现有审阅、应用和运行入口处理。代码子进程不是 OS 沙箱，权限开关也不等于操作系统级代码隔离。维护任务的验证继续只使用隔离 fixture，不修改或运行用户要求保留的实际流程。

## 全局对话管理与委派

`workbench.inspect` 的 `section: statistics` 读取最近7或30天的只读统计：对话、执行成败与耗时、已采集模型Token、最近上下文和登记产物。独立助手由服务端绑定当前工作流，仅返回该对象，不包含全局汇总或其它会话；总控沿用工作流读取及跨工作流读取权限。统计响应只含有界元数据，不含提示词、聊天正文、业务代码、文件路径或认证值。未采集和部分采集不证明零消耗，最近上下文不代表累计用量。详见[统计口径](workbench-statistics.md)。

全局历史补齐是 `ui-only`：由用户在统计页明确触发 `POST /api/statistics/history`，写入数字缓存，不写聊天或业务状态。助手可以读取补齐后的受限统计；跨全部本地会话的批量补齐缓存入口没有作为模型mutation工具开放。该接口只接受空对象，用户不能提交任意会话、数据库路径或profile；CSRF和Origin检查与现有写接口一致。普通统计GET保持只读，不自动补齐。

“对话管理”集中展示正常工作流的独立会话与总控主题，回收站会话不展示、不计入数量或筛选，恢复工作流后重新显示原会话。工作流会话沿用工作流 ID，各总控主题有独立身份、消息历史、待处理事项和诊断进度。旧全局会话 `global-application` 作为历史入口保留，不把其中消息分配或合并到工作流。普通任务保留原任务详情入口；旧项目路由兼容进入管理页。新主题、目录读取和界面切换都不改变工作流文档、运行或审核。

目录只读投影已有记录，尚无消息的工作流仍有独立入口，不为浏览目录写入空会话。总控先用 `conversations.list` 查看有界摘要，按问题使用 `conversation.inspect` 展开指定工作流的消息和待处理元数据；结果带分页或截断标记。该工具不附带私有会话字段、节点代码配置、检查点或学习／反馈材料。需要运行详情时继续按实际身份调用 `workflow.run`，会话文案不取代运行事实。禁止将所有会话正文预先灌入总控提示词。

会话工具需要总控的工作流读取与跨工作流读取权限。`conversation.delegate` 另需管理权限，以及本轮人工消息中明确的委派要求与目标；它向目标会话写入只读诊断任务，不是执行工作流。版本和稳定操作 ID 保证幂等。委派立即返回目标消息身份和当前进度，后续用 `conversation.inspect` 核对，不在同次调用中持续等待子模型。相同操作重复读取原任务；中断、失败或重启不重发。

子助手由服务端固定为目标工作流的只读身份：沿用其工作文件夹及人工权限，并进一步关闭提案、运行、审核、学习和聊天事项结束等路径。模型参数、委派正文和引用材料不能解除只读限制。总控的管理权限不会下传；诊断完成不代表已修复。需要修改时另走受控提案、用户应用和独立执行验证。

总控主题由用户在管理页创建，助手没有创建主题或修改权限的工具。主题隔离覆盖消息幂等、`replyToTurnId`、`retryOfTurnId`、检查点、并发任务、操作回执、事件和界面缓存。每个主题同时处理一条消息，并受总体并发上限约束；事件带会话身份，返回其它主题的迟到响应不能覆盖当前面板。跨会话回复、重试或操作应明确拒绝。新增主题与迁移只补充身份映射或元数据，既有正文、消息身份与业务现场保留。会话是持久历史和权限范围，不是为每条工作流常驻一个模型进程。

## 扩展流程

1. **核对现有接口。** 阅读共享能力目录、相关节点模型与工具处理器；确认要新增的是产品能力、助手入口还是缺失说明。已有能力先补真实发现和组合路径，保留其类型、产物及审批边界。完成标准：新增行为能够映射到明确的执行／提案／界面接口。
2. **实现同一条调用链。** 先完成领域接口和必要校验，再登记能力与工具 schema，接入 dispatcher。工具参数由接口定义约束；新增工具不因此开放任意 shell、无范围文件访问或软件源码补丁。完成标准：目录声明与实际处理器逐项对应，未实现的分支明确不可用。
3. **同步发现与说明。** 更新受影响的节点契约、内部 Skill 注册信息和按需加载的说明；提示词只负责选择这些真实能力。保持描述中的输入、代码函数体、返回类型、工作目录、依赖及异常语义与执行器一致。完成标准：助手无需用户重贴应用已有说明，就能找到正确接口；Skill 没有声明接口之外的权限。
4. **验证真实边界。** 通过与应用助手相同的 schema、dispatcher 和节点模型运行隔离回归，同时验证成功路径与拒绝路径。界面功能实际打开页面检查；依赖未知时保留“未确认”，不能用 fixture 成功冒充本机或业务运行成功。完成标准：工具广告、调用参数、实际结果及能力状态一致。
5. **更新交付资料。** 更新受影响的 README、架构和操作说明，记录已运行检查及未覆盖边界；源码和脱敏 fixture 可提交，私人运行、诊断截图与业务产物保留在忽略目录。

说明更新不是一律增加新 Skill。已有说明能容纳同一能力时原位维护；只有独立的触发条件、组合方法或专业知识需要单独承载时才登记新 Skill。内部 Skill 仍通过注册表发现，保持明确的加载条件和有界内容。

## 诊断编排与证据复用

新增诊断能力先确定首轮所需的最小摘要，其余详情通过现有工具按需读取。保留所选旧运行、最新运行和草稿的独立身份、版本及截断标记；压缩不能把旧证据换成当前事实，也不能把未读取等同于检查通过。

工具进入批量路径前明确其只读性、参数、角色和对象校验；调度器先验证整批，再执行允许的检查。提案、采集、工作流管理写入及网络探测保持独立调用。工具 schema 的说明文字不能代替处理器校验，也不能将新的写操作自动纳入批量或缓存。

诊断检查点仅由服务端生成并保存脱敏、有界证据。复用必须核对上下文、能力版本与当前工具契约，使用每条证据的采集时间判断过期；跨轮业务结果限于当前摘要能核对身份和版本的工作流及已结束运行。会话历史、Hermes 缓存目录、其它业务目标与依赖当前外部状态的结果重新读取。修改工具参数、效果或权限时使旧检查点失效。检查点不是模型记忆、操作授权或续跑指令。失败、取消和重启保留已完成回执及失败阶段，不能重放结果未知的操作。

回归应覆盖压缩后身份和错误仍可辨认、重复读取去重、整批拒绝无执行、过期与上下文变化失效、方案失败停止，以及超时后证据和阶段仍可读取。详见 [上下文、进度与中断](application-diagnostics.md#上下文进度与中断)。

## AI意图与处理流程

自由消息先由受保护的轻量模型判断类型，用户不手选类型，服务端也不靠句首规则跳过这一步。分类输入不含工具目录、日志或节点代码；分类响应不能携带工具、操作或权限。创建／修改使用专用候选生成，诊断才进入工具编排；反馈／长期改进准备已有受控动作。分类前后固定身份、模型路由、轮次总截止与权限检查，分类失败不自动转诊断。精确运行、审核、结束聊天事项等命令继续使用原有绑定校验。

新增对话功能时同步分类枚举、实际处理分支、目录说明与真实入口测试；类型名称不是执行或越权授权。简单提案按需提供相关契约，复杂图保留完整契约回退；无效候选最多一次纠错，副作用未知仍不重放。

## 助手模型故障兜底

助手对话失败或超时优先用 `assistant.diagnose`，按工作流或总控会话解析轮次后再读取控制会话元数据；模型不能提交session、路径或查询。独立助手受当前工作流及读取开关约束，总控另需软件日志权限，跨目标继续验证跨工作流权限。控制会话正文仍不开放 `session.history`。当前策略与历史策略分别报告，未采集数据和中断时零计量保持未知。该诊断同轮可复用，跨轮重新读取。

`assistant.probe` 是有成本的固定模型短请求，非普通只读查询；每个实际诊断轮次最多一次，不批量、跨轮缓存或自动重试，不能指定提示词与模型。它使用父诊断固定路由及更早截止；短请求通过不是原复杂任务修复证明。只读委派不提供探测。首次输出、流空闲和总截止由控制器执行，助手不能修改人工权限、默认配置或源码来解除限制。可诊断、提案、应用和实际业务验收分别记录；外部持续无响应、权限不足或软件源码缺陷要保留证据与明确边界。

## 会话事项与业务状态

会话 GET 响应提供只读的待处理状态投影；折叠和明确重试沿用同一聊天界面。用户明确说“这个问题解决了”或“不用处理了”时，本地会话指令可结束明确关联或唯一的聊天事项；多项候选通过原对话的编号选择并重新核对，疑问、否定和引用不触发结束。该指令属于 `available` 的 `conversation-command` 入口，不新增模型可调用的结束或批准工具；折叠及手动按钮仍是界面控制。

成功重试只接续有明确身份且请求与范围一致的旧助手失败；审核卡按真实运行、节点及尝试核对，未知状态保留。用户结束关注保存聊天处理记录并保留原文、证据和操作结果，不改变运行或人工审核。模型回复完成、提案应用或聊天事项结束都不能当作业务已修复。扩展时覆盖跨对象拒绝、幂等提交、歧义候选过期和真实审核仍阻塞，详细语义见 [待处理事项](workflow-conversation.md#待处理事项)。

## 业务代码与源码保护

业务流程可以在用户授权范围内包含可信本地 JavaScript／Python 代码候选。助手通过已有节点配置提出候选，用户审阅后应用到草稿，实际运行继续走预检、调度和产物校验。该路径不授予修改应用源码、绕过人工审核或直接改数据库的权限。

代码能力说明应包含执行函数体契约、真实上下文、工作目录、JSON 大小限制、日志与结果通道、超时／停止机制，以及文件声明与登记要求。明确哪些依赖已经探测、哪些仍未验证。代码子进程具备本机用户权限；独立进程、最小环境和产物路径校验不构成 OS 沙箱。

若用户要求改变节点类型、保留节点 ID 或重新绑定产物，先核对当前编辑命令是否支持。缺少受控操作时标为接口缺口；不能把修改整个流程 JSON、直接写数据库或伪造回执当作实现该功能。

## 新增 mutation 的完成条件

每个新增写操作都应能回答以下问题，并由同接口测试覆盖：

- **作用范围：** 操作属于哪个工作流、节点、运行、尝试、产物或明确目录；对象之间的归属如何验证。
- **版本：** 使用哪个草稿修订、运行快照、Skill 指纹、尝试 ID 或产物 SHA；过期请求如何拒绝。
- **幂等：** 哪个稳定消息／操作 ID 区分重复提交；相同 ID 的不同内容如何拒绝；未确认副作用如何标记。
- **可复核结果：** 应用后读回哪个版本或回执；文件是否存在、是否归本次运行且哈希可核对；提案和实际完成如何区分。
- **失败与取消：** 部分成功如何保留，取消能停止什么，哪些副作用无法撤销，重启是否会重放。

复用已有领域校验，而不是在助手或协议适配器里复制较弱版本。界面中的图片／人工审核继续由用户决定，文本“已修复”不能代替实际验收。

## 回归与运行证据

默认回归使用隔离 fixture，不修改用户认证、现有流程或正式运行，不隐式发起真实推理。测试至少覆盖：目录与处理器对应、真实参数／返回形状、未知参数拒绝、缺依赖、过期版本、重复提交、失败／取消、人工设置变更，以及跨角色／工作流／目录和受保护源码／学习证据的拒绝边界。

用户明确要求保留当前流程、自己逐步体验时，这一限制覆盖验收阶段：仅验证隔离 fixture，不改真实节点、连线、业务代码、配置与记录，不启动或重试实际业务，也不直接改数据库。不能因为基础设施测试通过就代用户应用候选或修复现场。

对代码节点应验证真实 worker 契约，而不只断言提示词中含“Python”；对能力发现应使用真实目录形状，而不在测试中提前补入生产目录没有的字段；对截图应核对真实像素和来源，DOM 摘要不能冒充截图。

先运行受影响模块测试，再按仓库约定完成必要回归与 Git 边界检查。文档和最终说明分别列出 fixture、实际本机依赖、真实模型、真实文件及用户视觉验收的证据，不将其中一种替代另一种。

## MCP 复用边界

当前没有对外 MCP server。共享工具 schema 和 dispatcher 是后续适配的复用基础，不代表已经提供 MCP 连接地址。

未来增加 MCP 时，适配器只负责协议封装、调用身份与上下文转换，实际能力继续进入同一 dispatcher、参数校验、作用范围、版本、幂等和结果投影。MCP 不能另起一套较宽权限，不能透传 Hermes 原生工具、认证或任意文件访问，也不能因为 Skill 描述了某项能力就自动授予调用权限。
