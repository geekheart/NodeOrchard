# 应用助手能力维护与扩展

本页用于新增功能、改变节点／执行接口、增加诊断工具、扩展内部 Skill 或接入 MCP 时同步维护助手能力。目标是让助手能主动发现真实接口，并按相同校验提出或执行获准操作。能力说明不替代实现，工具存在不代表前置条件已经满足。

## 权威来源

| 层 | 权威内容 | 维护要求 |
| --- | --- | --- |
| `shared/workflow/workflow-capability-contract.mjs` | 浏览器与后端共用的能力身份、边界及节点契约 | 保持纯模型，不读取本机文件、依赖、认证或数据库 |
| `shared/workflow/workflow-review-revision.mjs` | 冻结运行的修改策略、直接 Skill 消费者与历史修改计数 | 审核界面、聊天和执行器共用；人工修改不限次数，不依据代码字串推断自然语言修改能力 |
| `src/application-capabilities.mjs` | 当前应用的能力目录、节点说明及可用性投影 | 从真实共享模型及处理器派生，区分产品支持与本机就绪状态 |
| 会话权限模块及人工权限设置 | 服务端角色、工具准入、对象归属与工作目录边界 | 身份由对话入口绑定；配置由设置页提交，模型参数与提示词不能提升权限 |
| 应用工具的 schema 和 dispatcher | 工具名称、参数与真正的调用权限 | 每个已广告工具有对应处理器；未知工具和多余参数明确拒绝 |
| `src/assistant-diagnostic-turn.mjs` 与对话持久化模块 | 紧凑上下文、阶段、检查点与证据有效期 | 保留对象身份和省略标记；复用不扩权，失败与重启不重放 |
| `src/application-maintenance.mjs` 与隔离复现／验证模块 | 持久维护任务、单节点复现、相关源码测试和回读 | 绑定人工来源与修订；只读验证和源码修改分权，隔离结果不冒充业务恢复，见[总控持续维护](application-maintenance.md) |
| `src/application-conversation-hub.mjs` 与工作流／总控会话存储 | 会话目录、主题隔离、历史读取与只读委派 | 先读摘要再按需展开，消息和操作始终绑定目标会话，旧记录保留 |
| 工作流文件夹、包模块与 `workflow.folder` | 归属目录、便携包及历史导入身份 | 目录读取不执行打包；本机打开与导入为界面入口；导入不增加权限，见[工作流文件夹与便携包](workflow-packages.md) |
| `workflow-conversation-context.mjs` 与 `workflow.conversation` | 完整聊天文件、版本／SHA 绑定的恢复上下文、有界全文检索 | 早期目标与阶段只作历史数据；沿当前权限，不恢复旧授权或原生会话，见[对话文件与上下文恢复](workflow-packages.md#对话文件与上下文恢复) |
| 工作流素材登记、`workflow.attachments` 与 `workflow.attachment.read` | 当前获准工作流的素材列表、SHA 身份与有界文本读取 | 只接受登记身份；图片复用受保护的原生内容接口，二进制不冒充已解析正文，见[聊天素材](workflow-packages.md#聊天素材) |
| `src/workflows/workflow-examples.mjs` | 固定示例目录、默认输入、学习配置及实际 Skill 指纹 | `workbench.inspect` 可读目录元数据；载入是界面入口，依赖未就绪时返回明确条件，见[示例目录](#示例目录) |
| `workflow-learning-scope.mjs` 与学习编排／优化器 | Skill、指定工具及内部业务图的候选范围、评估和应用 | 前后端共用范围与快照守卫；训练证据用于优化，完整训练／验证用于评估，见[学习范围](#学习范围) |
| `src/application-assistant-skills.mjs` 与 `assistant-skills/` | 内部 Skill 的固定目录及如何组合、选择和解释已有接口 | 由注册表发现并按需读取，不扫描用户业务 Skill，不把说明文字视为新增工具授权 |
| Skill 来源与 `workbench.inspect(section="skills")` | 原生／工作台内置／生成来源和删除资格的有界元数据 | 正文及学习证据不展开，人工删除复核来源、版本与引用；管理内部指令不作为工作流节点，见[来源与删除](skill-integrations.md#来源与删除) |
| `shared/keyboard-shortcuts.mjs` 与偏好设置 | 用户快捷键操作、生效范围、组合与冲突规则 | 设置表、聊天、编辑器共用；助手只读当前偏好，不提供改键或扩大执行权限的工具 |
| 节点规划、执行、文件与审核模块 | 实际参数、类型、产物和状态语义 | 接口变更同时回写能力契约及相关说明 |

内部助手先使用 `app.capabilities` 获取能力范围，配置节点前按需调用 `node.describe`，检查解释器／依赖用 `runtime.inspect`，软件位置与版本启动用 `runtime.software.inspect`，已存Python节点语法用 `runtime.code.check`。具体参数、返回字段和可调用的内部 Skill 以当前工具目录及 schema 为准；本页不复制可执行 schema。[软件与脚本诊断](application-diagnostics.md#软件与脚本诊断)说明发现、启动、静态检查及真实业务的验证边界。

例如，工具与代码节点的 Python 函数体、`input`／`context`、输出 JSON、文件产物目录和依赖条件应能通过能力说明取得。不能因为注册工具目录没有 XLSX 导出器，就断言已有 Python 代码节点也不能产生工作簿；也不能因为执行器支持 Python，就承诺第三方包已安装或节点可以保持原 ID 换型。

运行时合约按语言说明字段访问：schema2 文件目录分别为 JavaScript 的 `context.outputDirectory` 和 Python 的 `context['outputDirectory']`。Python 上下文是普通 `dict`；JSON 对象输入解码为 `dict`、数组为 `list`，须检查输入形状并用方括号或 `dict.get` 读取对象字段。规划提示与 `node.describe` 共用这份真实合约，不把 JavaScript 的属性访问写法套用到 Python。

## 能力状态

新增可由代码完成的用户操作，应同步提供或扩展受控助手工具。人工审核、认证等确需用户处理的入口保留明确原因；不能只把新功能列入目录，就声称助手已经能操作。

| 状态 | 含义 | 助手应如何处理 |
| --- | --- | --- |
| `available` | 当前接口允许调用该能力，实际依赖和对象范围已声明 | 检查所需运行时条件，再通过对应工具调用并核对结果 |
| `proposal-only` | 可以生成可审阅候选，不能由这项能力直接执行业务 | 展示修改范围、候选与应用入口；应用和运行分别报告 |
| `ui-only` | 产品界面支持，但当前助手没有相应受控操作接口 | 说明界面入口或明确接口缺口；不虚构工具调用 |
| `unavailable` | 处理器未实现、依赖不满足或当前对象不支持 | 返回具体原因与所缺条件，不声称已经执行或验证 |

产品能力和运行时状态分别判断。已注册代码节点不等于某个 Python 包可导入；模型目录可读不等于账号已认证；预检通过不等于文件已经生成；隔离浏览器截图不等于用户当前标签页截图。运行时不应只依据提示词或旧文档推断就绪。

应用工作流修改时，新增节点，或连线新增、删除、改接后自动按依赖布局；纯配置、手动拖动和方向键移动保持现有布局。独立会话由编辑器按实际卡片尺寸排布，总控由服务端使用同一算法和默认尺寸保存；布局是应用后的呈现行为，不新增工具或运行权限。方案预应用仍校验完整指纹，仅会触发布局的修改回执允许当前层位置与视口不同，所有业务内容及嵌套流程仍须一致；纯坐标候选仍须精确符合请求。

## 会话权限与人工设置

独立会话由服务端绑定当前工作流，总控会话取得单独的服务端身份。模型只能选择该身份实际广告的工具；dispatcher 在读取和执行前重新校验配置与对象归属。省略目标时使用当前工作流，显式传入其它工作流、运行、会话或产物的 ID 不能越过归属检查。权限变化后，旧工具目录、诊断检查点和重试内容不构成继续访问的授权。

| 身份 | 可分配能力 | 固定边界 |
| --- | --- | --- |
| 独立工作流助手 | 读取当前工作流和运行日志；提出工作流／节点修改；派生业务代码节点；读取工作资料；受控截图与短录制 | 当前工作流与服务端绑定的工作文件夹，不取得其它工作流、全局软件日志或流程管理权限 |
| 总控助手 | 以上能力，以及跨工作流读取、复制、创建测试工作流、移入回收站、读取软件日志；人工开启后可用实验性源码修复 | 仅通过目录中的受控接口；流程删除保留恢复途径，创建与复制不自动运行；源码修复保护权限实现与用户数据 |

设置页的“助手权限”分别控制两种身份的能力。用户通过设置表单修改，保存需当前权限版本；版本变化时保留未保存选择并提示重新读取。任何助手均没有修改权限设置的工具；模型输出、浏览器诊断代理或未来 MCP 适配器不能取得该入口。此保护约束应用助手接口，不能替代任意业务代码执行所需的操作系统隔离。总控身份不等于软件管理员 shell 权限，双方都没有任意本机文件工具；源码写入仅限人工开启的实验性总控受控修复，独立会话与只读委派保持原限制。

总控管理入口为 `workflow.copy`、`workflow.create-test` 和 `workflow.delete`：写入使用稳定操作 ID 及预期修订，重复同内容读回原回执，不同内容复用 ID 明确拒绝；未确定结果保持未知，不自动重放。删除直接移入可恢复回收站，并在同一事务内暂停定时任务；当前节点编辑器随之卸载，保留本地草稿、历史与产物。恢复由界面更新为活动状态，用户明确打开后才加载，定时任务保持暂停。节点编辑器只加载活动记录，旧归档直链或上次选中缓存不能载入回收站流程。该界面生命周期规则不新增模型工具或权限；助手没有恢复或永久删除接口。复制保留业务节点但清空交付目录，不复制运行、聊天和定时任务；测试流程带明确测试名称，两者均不启动运行。`app.logs` 按等级、模块、时间及关联ID读取有界持久元数据，支持跨启动分页；当前进程Hermes窗口单独标识。不接受任意路径或日志写入，详见[应用日志](application-logging.md)。

总控可沿用 `app.logs` 读取 `hermes.proxy.environment` 的固定来源、状态、诊断码和协议数量，帮助区分显式环境、系统继承与读取失败；日志不含代理地址或凭据，不能据此宣称网络已连通。此能力为只读诊断，不新增查询任意系统配置、修改代理或重跑工作流的权限，完整规则见[代理继承](hermes-protocol.md#代理继承)。

管理权限不是任意轮次的修改授权。服务端从本轮人工消息核对管理动作与目标；只读诊断、保留现场、否定或引用中的命令不能授权写入，不明确时提示用户明确请求。操作 ID 由服务端按消息及操作内容绑定，模型更换 ID 不能重复创建；回执身份单独持久保留，不作为可重放缓存。

独立会话应用修改前先通过只读权限与候选指纹校验，撤销权限后的旧建议不会先改画布再报错。业务代码、表达式、嵌入子流程及工作流引用也接受相同范围校验。

独立助手的工作文件夹由服务端绑定到自身工作流目录；总控沿用已配置工作区与默认工作目录范围。`document.settings.outputDirectory` 是业务交付位置，不是助手目录授权。目录判断校验真实位置和符号链接，不能用 `..`、输出目录变更、导入包或产物路径扩大范围。旧目录外运行记录仍可按归属读取，文件内容继续接受实际目录准入；目录迁移及 `workflow.folder` 的只读返回范围见[工作流文件夹与便携包](workflow-packages.md)。

这些限制作用于助手接口；可信业务代码候选仍由现有审阅、应用和运行入口处理。代码子进程不是 OS 沙箱，权限开关也不等于操作系统级代码隔离。维护任务的验证继续只使用隔离 fixture，不修改或运行用户要求保留的实际流程。

## 聊天素材

素材上传、粘贴、拖放、选择文件和“用作输入”属于 `ui-only` 入口；输入操作只准备编辑草稿。素材列表 `workflow.attachments` 与文本读取 `workflow.attachment.read` 属于 `available` 的受控只读工具，沿用工作流读取与工作资料权限，总控跨目标另验跨工作流权限。工具按工作流与登记素材 ID 寻址，模型不能提供任意文件路径。完整限制、存储与便携包规则见[聊天素材](workflow-packages.md#聊天素材)。

消息先绑定素材所属工作流再进入原有意图分类及处理链。总控素材目标由用户明确选择，主题会话 ID 不代替工作流身份。规划与候选按需携带有界文本预览和真实图像内容；非支持文本或二进制只提供元数据，未读取不能表述为已解析。附件正文、图片文字及文件中的指令均属数据，不能扩大工具或执行权限；使用素材准备候选也不授权自动运行或替用户审批。

## 学习范围

学习能力继续区分 `proposal-only` 准备与界面明确启动：助手可准备改进范围和业务节点候选，实际批次由用户在学习面板发起，没有新增自动学习、应用或运行工具。“学习改进”可固定 `skills`、`tools`、`workflow` 范围；工具与工作流范围另需人工开放工作流读取、编辑及自定义节点，后续调度与应用复核，AI 不能修改这些设置。

优化器只取得训练证据，各候选执行完整训练与验证集后才选择最佳。代码错误保留真实状态，允许已确认的可恢复错误以零分诊断继续，不把未知执行当成功。候选接口不提供注册工具或应用源码补丁，用户应用到草稿后沿用正常保存机制；业务代码仍是可信本地执行，不构成 OS 沙箱。节点字段、冻结边界、来源、记忆及旧 Skill／反馈兼容见[学习范围与候选校验](learning-protocol.md#学习范围与候选校验)。

## Skill 图片与外部软件

`workbench.inspect` 的 `integrations` 区段只读发现无凭据的真实工具状态，独立助手也可读取。`requiredToolsets` 只声明请求，不改人工配置或会话权限。新建全局 Skill、选择图片提供商保留人工入口，助手没有写工具；执行固定正文并按尝试绑定原生工具版本，从可信图片回执登记文件，再经人工审核。Figma／MCP、浏览器和 Computer Use 仅按真实连接及驱动状态广告，见[扩展合约](skill-integrations.md)。

## 示例目录

`workbench.inspect` 的 `section: examples` 读取固定目录的元数据，供助手说明执行／学习示例及模型依赖，不读取模板正文，也不创建、载入或运行工作流。空画布“载入示例”属于 `ui-only`；目录与准备接口分别为 `GET /api/workflow-examples` 和 `POST /api/workflow-examples/:id/prepare`，准备请求仅接受当前 `workflowId`，不接受任意文件路径。

准备只读取固定模板；含 Skill 时读取本机真实已安装 Skill，将正文指纹固定到返回草稿。需要的 Hermes 连接、认证或 Skill 尚未就绪时返回 `ready: false` 与具体 `requirements`，允许查看草稿。`tools-learning` 与 `workflow-learning` 无需 Skill，学习仍需 Hermes 与可用模型，并检查人工设置中的工作流读取、编辑和自定义节点权限；缺少权限同样列为未满足条件。不能把目录存在、草稿已载入或 `ready: true` 当作运行成功。载入保留当前工作流 ID，不自动执行、学习或审批。

目录包含 6 个执行和 4 个学习模板。学习配置经学习面板 `setConfig` 预填，并从实际学习支路取得 `scope` 和目标节点，不将工具／工作流范围强制当成 Skill；数据集导入不承担完整配置加载。四个学习示例分别演示 Skill 正文改进、工具业务代码修改或内部业务节点替换与重连，具体样例、依赖与审核等待行为以[载入示例](user-guide.md#载入示例)为准。助手仍只读目录元数据，实际学习与最佳候选应用沿用[学习范围](#学习范围)的明确界面入口。

## 节点派生目录

`workbench.inspect` 的 `section: node-derivations` 读取节点派生目录，返回 `derivations` 及父级、固定版本等来源元数据；旧区段 `node-presets` 继续返回 `presets`，仅作接口兼容，权限范围相同。节点派生的创建与版本发布继续为 `ui-only`；读取目录不授权保存、运行节点或修改来源。基础父级、继续派生、新版本及历史未知来源的合约见[节点派生](workflow-node-system.md#节点派生)。内部 `preset` 名称保留接口兼容，不再作为界面术语。

## 全局对话管理与委派

`workbench.inspect` 的 `section: statistics` 读取最近7或30天的只读统计：对话、执行成败与耗时、已采集模型Token、最近上下文和登记产物。独立助手由服务端绑定当前工作流，仅返回该对象，不包含全局汇总或其它会话；总控沿用工作流读取及跨工作流读取权限。统计响应只含有界元数据，不含提示词、聊天正文、业务代码、文件路径或认证值。未采集和部分采集不证明零消耗，最近上下文不代表累计用量。详见[统计口径](workbench-statistics.md)。

全局历史补齐是 `ui-only`：由用户在统计页明确触发 `POST /api/statistics/history`，写入数字缓存，不写聊天或业务状态。助手可以读取补齐后的受限统计；跨全部本地会话的批量补齐缓存入口没有作为模型mutation工具开放。该接口只接受空对象，用户不能提交任意会话、数据库路径或profile；CSRF和Origin检查与现有写接口一致。普通统计GET保持只读，不自动补齐。

“对话管理”集中展示正常工作流的独立会话与总控主题，回收站会话不展示、不计入数量或筛选，恢复工作流后重新显示原会话。工作流会话沿用工作流 ID，各总控主题有独立身份、消息历史、待处理事项和诊断进度。旧全局会话 `global-application` 作为历史入口保留，不把其中消息分配或合并到工作流。普通任务保留原任务详情入口；旧项目路由兼容进入管理页。新主题、目录读取和界面切换都不改变工作流文档、运行或审核。

目录只读投影已有记录，尚无消息的工作流仍有独立入口，不为浏览目录写入空会话。总控先用 `conversations.list` 查看有界摘要，按问题使用 `conversation.inspect` 展开指定工作流的消息和待处理元数据；结果带分页或截断标记。该工具不附带私有会话字段、节点代码配置、检查点或学习／反馈材料。需要运行详情时继续按实际身份调用 `workflow.run`，会话文案不取代运行事实。禁止将所有会话正文预先灌入总控提示词。

会话工具需要总控的工作流读取与跨工作流读取权限。`conversation.delegate` 另需管理权限，以及本轮人工消息中明确的委派要求与目标；它向目标会话写入只读诊断任务，不是执行工作流。版本和稳定操作 ID 保证幂等。委派立即返回目标消息身份和当前进度，后续用 `conversation.inspect` 核对，不在同次调用中持续等待子模型。相同操作重复读取原任务；中断、失败或重启不重发。

子助手由服务端固定为目标工作流的只读身份：沿用其工作文件夹及人工权限，并进一步关闭提案、运行、审核、学习和聊天事项结束等路径。模型参数、委派正文和引用材料不能解除只读限制。总控的管理权限不会下传；诊断完成不代表已修复。需要修改时另走受控提案、用户应用和独立执行验证。

独立会话可在本轮排错请求下通过 `conversation.escalate`登记或启动来源绑定的总控只读诊断，使用 `conversation.escalation`在原聊天读取结论。该方向与 `conversation.delegate`分开：受总控已有读取权限约束，不需管理或源码写权限；按来源轮次最多启动一次，blocked／停止／重启不自动重放。总控子诊断固定只读，不能反向委派；完整准入、摘要与代码检查边界见[软件与脚本诊断](application-diagnostics.md#软件与脚本诊断)。

普通总控主题由用户在管理页创建；升级工具仅创建受来源身份绑定的只读主题，没有任意创建、合并历史或修改权限的工具。主题隔离覆盖消息幂等、`replyToTurnId`、`retryOfTurnId`、检查点、并发任务、操作回执、事件和界面缓存。每个主题同时处理一条消息，并受总体并发上限约束；事件带会话身份，返回其它主题的迟到响应不能覆盖当前面板。跨会话回复、重试或操作应明确拒绝。新增主题与迁移只补充身份映射或元数据，既有正文、消息身份与业务现场保留。会话是持久历史和权限范围，不是为每条工作流常驻一个模型进程。


### 总控归档与工作流聊天引用

新建、归档和恢复总控主题属于 `ui-only`：由用户管理当前上下文与可写会话身份，模型不能自行迁移、归档或恢复其来源会话。聊天引用的选择由用户完成，已有 `conversation.inspect` 精确只读入口为 `available`；引用不新增长期模型进程或会话管理 mutation。

总控新会话可与归档当前主题一并提交：创建请求沿用 `clientConversationId` 幂等身份，另绑定 `archiveConversationId` 和 `expectedArchiveRevision`；两项成功后才切换。其它主题、原消息和来源工作流保持原身份。普通独立创建仍可省略归档目标。生命周期单独保存 `lifecycle`、`lifecycleRevision` 和 `archivedAt`，旧 `global-application` 不需迁移正文也可归档。

管理页默认列活动总控主题，归档主题从独立归档入口回看及恢复。归档可读，消息发送、候选应用和维护续接均须先恢复；恢复只改变生命周期，不重发模型、重放动作或改变原升级诊断的只读身份。归档／恢复使用稳定 `operationId` 与预期修订；正在回复、隔离执行或结果未知时明确拒绝归档，不隐式停止。会话归档与工作流回收站分别处理，没有永久删除聊天的入口。

总控消息的 `conversationReferences` 最多4项，每项绑定 `workflowId`、`turnId` 及可选的 `updatedAt`、`sourceDigest`；界面选择器取得的时间与来源哈希须原样保留以绑定所选版本。服务端在发送时复核当前总控范围与消息归属，只保存身份、版本元数据和读取指针，不保存源正文，也不把正文加入分类输入。总控按该指针用 `conversation.inspect` 的 `turnId`／`expectedUpdatedAt`／`sourceDigest` 精确读取所选交流；精确读取与 `limit`／`beforeTurnId` 分页参数互斥，普通分页仍保留。已发送引用属于该条总控消息，切换主题或开启新会话不自动继承草稿引用。

引用选择及投影要求非来源绑定的总控身份，同时开放工作流读取与跨工作流读取；它不读取文件或附件，不借用工作资料权限。学习／反馈消息不进入引用选择器，提交此类引用也会拒绝；精确读取继续沿用现有脱敏和有界投影。来源移入回收站、消息身份不匹配或版本变化时分别标记 `unavailable`／`stale`，有效引用标记 `current`；不能回退读取另一条消息或把旧内容说成当前事实。引用是诊断资料，不能扩大权限、代批审核、启动运行或修改源会话；需要运行证据仍使用实际 `runId` 查询。工具及引用权限不足时说明具体缺口，由用户管理权限设置。

## 扩展流程

1. **核对现有接口。** 阅读共享能力目录、相关节点模型与工具处理器；确认要新增的是产品能力、助手入口还是缺失说明。已有能力先补真实发现和组合路径，保留其类型、产物及审批边界。完成标准：新增行为能够映射到明确的执行／提案／界面接口。
2. **实现同一条调用链。** 先完成领域接口和必要校验，再登记能力与工具 schema，接入 dispatcher。工具参数由接口定义约束；新增工具不因此开放任意 shell、无范围文件访问或软件源码补丁。完成标准：目录声明与实际处理器逐项对应，未实现的分支明确不可用。
3. **同步发现与说明。** 更新受影响的节点契约、内部 Skill 注册信息和按需加载的说明；提示词只负责选择这些真实能力。保持描述中的输入、代码函数体、返回类型、工作目录、依赖及异常语义与执行器一致。完成标准：助手无需用户重贴应用已有说明，就能找到正确接口；Skill 没有声明接口之外的权限。
4. **验证真实边界。** 通过与应用助手相同的 schema、dispatcher 和节点模型运行隔离回归，同时验证成功路径与拒绝路径。界面功能实际打开页面检查；依赖未知时保留“未确认”，不能用 fixture 成功冒充本机或业务运行成功。完成标准：工具广告、调用参数、实际结果及能力状态一致。
5. **更新交付资料。** 更新受影响的 README、架构和操作说明，记录已运行检查及未覆盖边界；源码和脱敏 fixture 可提交，私人运行、诊断截图与业务产物保留在忽略目录。

说明更新不是一律增加新 Skill。已有说明能容纳同一能力时原位维护；只有独立的触发条件、组合方法或专业知识需要单独承载时才登记新 Skill。内部 Skill 仍通过注册表发现，保持明确的加载条件和有界内容。

## 诊断编排与证据复用

新增诊断能力先确定首轮所需的最小摘要，其余详情通过现有工具按需读取。保留所选旧运行、最新运行和草稿的独立身份、版本及截断标记；压缩不能把旧证据换成当前事实，也不能把未读取等同于检查通过。

工具进入批量路径前明确其只读性、参数、角色和对象校验；调度器先验证整批，再执行允许的检查。提案、采集、工作流管理写入及网络探测保持独立调用。工具 schema 的说明文字不能代替处理器校验，也不能将新的写操作自动纳入批量或缓存。

诊断检查点仅由服务端生成并保存脱敏、有界证据。复用必须核对上下文、能力版本与当前工具契约，使用每条证据的采集时间判断过期；跨轮业务结果限于当前摘要能核对身份和版本的工作流及已结束运行。会话历史、Hermes 缓存目录、其它业务目标与依赖当前外部状态的结果重新读取。修改工具参数、效果或权限时使旧检查点失效。检查点不是模型记忆、操作授权或续跑指令。失败、取消和重启保留已完成回执及失败阶段，不能重放结果未知的操作。

回归应覆盖压缩后身份和错误仍可辨认、重复读取去重、整批拒绝无执行、过期与上下文变化失效、方案失败停止，以及超时后证据和阶段仍可读取。详见 [上下文、进度与中断](application-diagnostics.md#上下文进度与中断)。

总控通过 `maintenance.task` 保存人工排错目标、阶段及证据，通过 `maintenance.experiment` 执行和回读隔离单节点复现或相关源码测试。每段预算结束保留任务与缺口，续接检查当前权限和修订；未知或重启不重放。源码只读测试独立于 `sourceRepair`，修改源码仍须人工开启并明确继续；实验通过仅对应所列快照，原工作流不修改、不运行。详细范围、状态和完成标准见[总控持续维护](application-maintenance.md)。

## AI意图与处理流程

自由消息先由受保护的轻量模型判断类型，用户不手选类型，服务端也不靠句首规则跳过这一步。分类输入不含工具目录、日志或节点代码；分类响应不能携带工具、操作或权限。创建／修改使用专用候选生成，诊断才进入工具编排；普通反馈／长期改进准备已有受控动作。通过版本与权限校验的显式产物修改请求，分类为 `workflow` 或 `feedback` 都可生成代码候选，保留原始分类；其它意图边界见[审核、重做与反馈](workflow-conversation.md#审核重做与反馈)。分类前后固定身份、模型路由和权限检查，默认无本地模型等待截止，分类失败不自动转诊断。精确运行、审核、结束聊天事项等命令继续使用原有绑定校验。

新增对话功能时同步分类枚举、实际处理分支、目录说明与真实入口测试；类型名称不是执行或越权授权。简单提案按需提供相关契约，复杂图保留完整契约回退；无效候选最多一次纠错，副作用未知仍不重放。

## 助手模型故障兜底

助手对话失败或超时优先用 `assistant.diagnose`，按工作流或总控会话解析轮次后再读取控制会话元数据；模型不能提交session、路径或查询。独立助手受当前工作流及读取开关约束，总控另需软件日志权限，跨目标继续验证跨工作流权限。控制会话正文仍不开放 `session.history`。当前策略与历史策略分别报告，未采集数据和中断时零计量保持未知。该诊断同轮可复用，跨轮重新读取。

`assistant.probe` 是有成本的固定模型短请求，非普通只读查询；每个实际诊断轮次最多一次，不批量、跨轮缓存或自动重试，不能指定提示词与模型。它使用父诊断固定路由，默认等待原生结果／错误或用户停止；短请求通过不是原复杂任务修复证明。只读委派不提供探测。默认首响应、流空闲和整轮期限均为 null，表示关闭本地模型等待限制；上游错误、连接中断、用户停止仍结束请求，不自动重放。显式有限控制参数只在明确调用中生效，助手不能修改人工权限或默认配置。可诊断、提案、应用和实际业务验收分别记录；外部持续无响应、权限不足或软件源码缺陷要保留证据与明确边界。

## 会话事项与业务状态

会话 GET 响应提供只读的待处理状态投影；折叠和明确重试沿用同一聊天界面。用户明确说“这个问题解决了”或“不用处理了”时，本地会话指令可结束明确关联或唯一的聊天事项；多项候选通过原对话的编号选择并重新核对，疑问、否定和引用不触发结束。该指令属于 `available` 的 `conversation-command` 入口，不新增模型可调用的结束或批准工具；折叠及手动按钮仍是界面控制。

提示“×”与“显示已隐藏 · N”仅为 `ui-only` 浏览器偏好，覆盖看板请求、独立／总控待处理组与单项、运行审批提示。隐藏绑定当前事项身份与版本，不改变会话 GET 投影、聊天处理记录或运行／审核状态；新事项及新审核版本重新提示。隐藏与恢复没有助手写入工具，也不扩展 `app.logs` 或其它读取权限，细节见[待处理事项](workflow-conversation.md#待处理事项)。

成功重试只接续有明确身份且请求与范围一致的旧助手失败；审核卡按真实运行、节点及尝试核对，未知状态保留。用户结束关注保存聊天处理记录并保留原文、证据和操作结果，不改变运行或人工审核。模型回复完成、提案应用或聊天事项结束都不能当作业务已修复。扩展时覆盖跨对象拒绝、幂等提交、歧义候选过期和真实审核仍阻塞，详细语义见 [待处理事项](workflow-conversation.md#待处理事项)。

## 业务代码与源码保护

业务流程可以在用户授权范围内包含可信本地 JavaScript／Python 代码候选。助手通过已有节点配置提出候选，用户审阅后应用到草稿，实际运行继续走预检、调度和产物校验。该路径不授予修改应用源码、绕过人工审核或直接改数据库的权限。

实验性总控源码修复是独立入口：`supervisor.sourceRepair` 默认关闭，仅人工设置可开启，按当前权限开放 `app.source.*` 工具族的目录、读取、修改、修复测试、历史和回滚能力。修改固定保护权限准入、凭据、Git 与用户数据，写入绑定预期 SHA 和操作身份；测试只在源码副本、临时数据与无网络 OS 沙箱中运行，无有效沙箱则拒绝。关闭开关后 AI 不能继续写入、调用修复测试或回滚，用户仍可在设置页查看记录并手动回滚；独立源码只读权限下的维护测试不授予这些写能力。工具边界、冲突与生效方式见[总控源码自修复](application-source-repair.md)；不提供自动重启、依赖安装或发布，也不授权修改、重跑真实工作流。

人工要求修改不限次数，历史修改计数不承担准入限制；自动重试、候选自动修复及循环执行继续遵守原有上限。审核修改须区分 Skill 反馈重做与代码候选。所有工具节点的产物反馈均由 AI 重生核心业务代码候选，即使下游连接 Skill 也不直接重跑工具。填写意见后单击“生成修改候选”，即将完整意见与版本绑定的 `revisionRequest` 提交到同一对话，启动 AI 分类，无需再发一条消息；版本绑定有效且分类为 `workflow` 或 `feedback` 时进入代码候选生成，权限沿用流程编辑和自定义节点设置。工具产物候选须包含实际业务代码变化，仅改标题或占位配置不能宣称已完成修改。候选经用户明确应用后修改草稿，后续需明确新建运行；旧运行和待审核产物保持原快照。人工批准／停止继续属于 `ui-only`，候选生成属于 `proposal-only`，不新增执行、审核或权限修改工具。身份绑定、其它意图边界和失败语义见[审核、重做与反馈](workflow-conversation.md#审核重做与反馈)。

代码能力说明应包含执行函数体契约、真实上下文、工作目录、JSON 大小限制、日志与结果通道、超时／停止机制，以及文件声明与登记要求。明确哪些依赖已经探测、哪些仍未验证。代码子进程具备本机用户权限；独立进程、最小环境和产物路径校验不构成 OS 沙箱。

若用户要求改变节点类型、保留节点 ID 或重新绑定产物，先核对当前编辑命令是否支持。缺少受控操作时标为接口缺口；不能把修改整个流程 JSON、直接写数据库或伪造回执当作实现该功能。

## 新增 mutation 的完成条件

每个新增写操作都应能回答以下问题，并由同接口测试覆盖：

- **作用范围：** 操作属于哪个工作流、节点、运行、尝试、产物或明确目录；对象之间的归属如何验证。
- **版本：** 使用哪个草稿修订、运行快照、Skill 指纹、尝试 ID 或产物 SHA；过期请求如何拒绝。
- **幂等：** 哪个稳定消息／操作 ID 区分重复提交；相同 ID 的不同内容如何拒绝；未确认副作用如何标记。
- **可复核结果：** 应用后读回哪个版本或回执；文件是否存在、是否归本次运行且哈希可核对；提案和实际完成如何区分。
- **失败与取消：** 部分成功如何保留，取消能停止什么，哪些副作用无法撤销，重启是否会重放。

复用已有领域校验，而不是在助手或协议适配器里复制较弱版本。界面中的图片／人工审核继续由用户决定，文本“已修复”不能代替实际验收。

## 回归与运行证据

默认回归使用隔离 fixture，不修改用户认证、现有流程或正式运行，不隐式发起真实推理。测试至少覆盖：目录与处理器对应、真实参数／返回形状、未知参数拒绝、缺依赖、过期版本、重复提交、失败／取消、人工设置变更，以及跨角色／工作流／目录和受保护源码／学习证据的拒绝边界。

用户明确要求保留当前流程、自己逐步体验时，这一限制覆盖验收阶段：仅验证隔离 fixture，不改真实节点、连线、业务代码、配置与记录，不启动或重试实际业务，也不直接改数据库。不能因为基础设施测试通过就代用户应用候选或修复现场。

对代码节点应验证真实 worker 契约，而不只断言提示词中含“Python”；对能力发现应使用真实目录形状，而不在测试中提前补入生产目录没有的字段；对截图应核对真实像素和来源，DOM 摘要不能冒充截图。

先运行受影响模块测试，再按仓库约定完成必要回归与 Git 边界检查。文档和最终说明分别列出 fixture、实际本机依赖、真实模型、真实文件及用户视觉验收的证据，不将其中一种替代另一种。

## MCP 复用边界

当前没有对外 MCP server。共享工具 schema 和 dispatcher 是后续适配的复用基础，不代表已经提供 MCP 连接地址。

未来增加 MCP 时，适配器只负责协议封装、调用身份与上下文转换，实际能力继续进入同一 dispatcher、参数校验、作用范围、版本、幂等和结果投影。MCP 不能另起一套较宽权限，不能透传 Hermes 原生工具、认证或任意文件访问，也不能因为 Skill 描述了某项能力就自动授予调用权限。

## 总控诊断扩展

请求链路由 `assistant.diagnose` 摘要和 `assistant.trace` 受控分页读取，复用日志与对象归属权限；历史缺失和不可观测阶段明确未知。`supervisor.sourceRead` 独立开放源码目录／读取，并可按维护准入验证只读源码副本；`sourceRepair` 继续单独控制补丁、修复测试、修复历史与回滚。`supervisor.modelExperiment` 及顶层 `modelExperimentLimits.maxInputCharacters` 仅人工设置；默认关闭，已授权总控可用 `assistant.experiment` 做单轮一次的合成模型近似实验，不执行业务、不读取原始prompt、不修改默认模型或权限。输出为软约束，有真实用量。模型实验不进入批量、只读委派或结果缓存；未确认操作不重放。接口与证据边界见[请求级链路与近似实验](application-diagnostics.md#请求级链路与近似实验)。

AI已分类为diagnose的实际处理分支会按受控意图加载诊断Skill，不依赖用户恰好使用“失败／超时”等关键词；关键词仅作为兼容的补充发现机制，不决定对话路由或权限。诊断复用近期有效短探测，长请求问题继续核对请求链路和实现，按可观察预测验证假设，区分应用控制故障与缺失的下游历史证据。
