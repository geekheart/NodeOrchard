# 区分方案、执行与交付

1. 通过 `workflow.run` 读取用户要验收的明确运行，核对状态、节点尝试和配置快照。新草稿不改变旧运行；比较新旧结果时分别保留两个运行身份。这个工具只读历史，不会启动工作流。
2. 所有必要步骤完成、没有阻塞或待处理错误后，才判断执行成功。对 Skill 使用必要的 `session.history` 核对正式结果；partialText、单条“已完成”文案和候选应用成功都不能代替终态。
3. 交付文件用 `artifact.inspect` 核对登记归属、版本及真实哈希，遵守其大小和格式限制。把元数据或哈希验证与业务内容验收分开；只能读取文本/JSON摘要时，不能声称已检查 Excel 单元格、图片效果或完整大文件内容。
4. 修复后尚无新运行时，明确“候选/配置已准备，执行未验证”，告知用户使用已有运行入口后再检查。界面问题可用 `browser.capture` 留下截图或短录制证据；页面复现成功不代替业务产物正确。

完成标准：说明实际验过的运行、产物及结果，指出未验证内容和下一步。以可读证据结束，不虚构文件、评分、自动重试或成功结论；不因验证任务修改用户真实工作流或重放业务操作。
