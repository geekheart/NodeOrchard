# NodeOrchard · 应用与部署参考

界面移除常驻助手介绍与操作教学；聊天命令、权限和执行流程保持原状。

工作流顶部操作采用图标按钮，完整操作名称由悬停提示和无障碍名称提供。

取消节点或连线选择后，属性栏自动关闭；重新选择时打开，保留未应用的节点配置。

新增或生成节点，以及新增、删除或改接连线后，自动按依赖布局并适应可见画布；修改与布局一次撤销即可恢复。纯属性修改、手动移动以及打开或导入已有流程保留原布局，不自动执行工作流。

统计页按工作流展示对话、模型与工具调用、运行成败和耗时、Token采集覆盖、最近上下文、登记产物与记录大小。仪表布局沿用主页面配色及深浅主题，按上海自然日查看最近7或30天；“补齐历史”只读读取Hermes已有计量，可靠归属后补入独立统计缓存，无可靠来源仍显示未知。网页不展示口径说明，开发说明见[统计口径](docs/workbench-statistics.md)。

工作流直接移入回收站，再恢复到工作流或确认永久删除。节点编辑器只加载活动工作流；当前流程移入回收站或永久删除后立即卸载，清除选中指针，保留本地草稿、历史与产物。旧归档记录也显示在回收站，旧链接与上次选中缓存不会加载它们；恢复只更新工作流库，明确打开后才加载。

进入 `#/workflows` 时，有效的当前活动选择仍可继续打开并重新校验；没有有效选择时显示空态，仅提供新建或返回看板入口，不自动选择其它工作流。详见[回收站与删除](docs/workflow-lifecycle.md)。

项目介绍、界面截图与完整首次部署流程见 [项目首页](../README.md)。本页保留详细目录与配置说明。

本机单用户应用，以 Hermes 为 Agent 核心，由 Hermes 管理模型连接、认证、Skills 和记忆。支持工作流看板、节点编排、AI 对话修改、并行调度、人工审核、定时运行及多样例学习。

Skills 页和节点选择器可新建 Skill，图片模板调用 Hermes 原生图像提供商，真实文件自动归集并等待人工审核。图片、浏览器、Computer Use 与已配置 MCP 显示真实就绪状态；Figma 等软件需先接入 Hermes，缺失配置不会冒充可运行。图像服务由用户选择，认证继续复用 Hermes，见[Skill 图片与外部工具](docs/skill-integrations.md)。

每条工作流的右侧会话独立承接任务配置、运行和结果反馈；默认自动判断意图，用户无需选择处理方式。固定需求保存为输入默认值，运行时无需重复填写；本次明确提供的输入覆盖默认值。画布可独立隐藏，其节点库、属性与工具一起隐藏，恢复画布时保留编辑布局。

聊天输入框可粘贴图片和文件，也可拖放或选择文件。素材保存在所属工作流中，总控添加前先选目标工作流；“用作输入”只准备编辑草稿。AI 图像查看、文本读取、容量和便携包规则见[聊天素材](docs/workflow-packages.md#聊天素材)。

空画布的“载入示例”分执行与学习两组，提供 10 个 schema2 模板：6 个执行、4 个学习，其中 3 个本地执行示例无需模型。学习覆盖 Skill、指定工具和整个业务工作流，包含完整支路及预填配置；后两种无需 Skill，但学习需要 Hermes、可用模型与人工开放的工作流读取、编辑和自定义节点权限。载入保留当前工作流 ID，不自动运行。实际 Skill 指纹、缺失条件及人工审核等待说明见[载入示例](docs/user-guide.md#载入示例)。

节点库的“节点派生”收纳从基础节点或已有派生节点生成的特色节点；目录、实例属性和保存时均展示直接父级，已有派生父级固定到具体版本。发布新版本与继续派生分别保留原父级、建立新父级关系，规则见[节点派生](docs/workflow-node-system.md#节点派生)。

“学习改进”可指定 Skill、工具／代码节点或整个内部业务流程；范围由画布固定，候选逐轮验证，最佳版本由用户应用到草稿。工具与工作流学习需人工开放工作流读取、编辑和自定义节点权限；代码在可信宿主运行，完整边界见[学习范围与候选校验](docs/learning-protocol.md#学习范围与候选校验)。

人工要求修改不限次数，已发生的修改次数仅保留为历史记录。Skill 目标可按反馈使用原运行快照重做；所有工具节点的产物反馈均由 AI 重生核心业务代码候选，下游连接 Skill 也不改变这一路径。填写意见并单击“生成修改候选”，即在同一对话提交意见并启动 AI 分类，无需再次发送。显式请求通过版本与权限绑定后，`workflow` 和 `feedback` 分类都可生成代码候选，保留原始分类；普通反馈保持原有处理流程。候选必须包含真实业务代码变化，用户审阅并应用草稿后，再明确发起新运行。旧运行及其产物保持原快照；自动重试、候选自动修复和循环执行仍遵守各自的限制，详见[审核、重做与反馈](docs/workflow-conversation.md#审核重做与反馈)。

“对话管理”替代原“项目”页，集中列出正常工作流的会话、待处理数量与最近消息，并提供总控主题入口。回收站会话不展示、不计数，恢复工作流后原会话重新出现。总控按问题分别建会话，按需读取或委派目标工作流的只读诊断；看板、设置等页面不再共用一个总控聊天上下文。旧工作流和聊天记录保留，原普通任务仍可从历史任务入口查看。权限开关继续由用户在设置页管理，具体范围见 [全局对话管理与委派](docs/application-assistant-capabilities.md#全局对话管理与委派)。

顶部提示横幅右侧的关闭按钮可隐藏当前消息；后续新提示仍会显示，Hermes 连接与运行状态不受影响。

所有 AI 对话默认使用 Ctrl+Enter 或 ⌘+Enter 发送；Enter 换行。设置页的快捷键操作表支持录制、禁用、恢复默认和保存，组合与生效范围共用同一契约，保存后各页面即时使用。默认表及交互边界见[快捷键](docs/keyboard-shortcuts.md)。

应用采用debug/info/warn/error/fatal分级结构化日志，关联HTTP请求、工作流、节点、会话和诊断阶段，受大小及时间限制持久保留。总控助手按既有日志权限直接查询，页面请求错误自动携带服务端关联ID；不记录完整聊天或业务输入输出，详见[应用日志](docs/application-logging.md)。

待处理区默认折叠并记住展开选择；看板请求、右侧待处理区与运行审批提示可用“×”本地隐藏，再由“显示已隐藏 · N”恢复。相同事项版本刷新后保持隐藏，新事项及新审核版本重新提示；隐藏不结束聊天关注、不审核或停止运行。已完成或被明确重试接续的聊天事项仍按原规则退出列表，原消息保留，详见 [待处理事项](docs/workflow-conversation.md#待处理事项)。

## 运行与工作环境

需要 Node.js ≥ 22.13。主应用使用 Node 内置模块，无需安装前端框架或独立数据库服务。**使用 AI 功能前，先按 [Hermes 官方指南](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)安装 Hermes Agent**，运行 `hermes model` 配置提供商和模型，再用 `hermes` 验证一次对话。当前适配已验证 Hermes 0.21.4。

从项目根目录运行 `npm --prefix workbench start`，或在本目录运行 `npm start`，打开 http://127.0.0.1:4318 。

默认查找 Hermes 安装 `~/.hermes/hermes-agent`，在界面点击“连接 Hermes”后读取当前模型与已配置目录。顶部可切换服务商和模型，选择由 Hermes 原生接口校验并持久化；新增提供商和认证先在 Hermes 完成，再刷新目录。支持 Hermes 已配置且认证已确认的提供商，ChatGPT 订阅是其中一种选择。纯本地工具／代码流程可离线运行；工程转换和编译需要相应本机依赖，缺失时明确报告。

macOS 的 Hermes 子进程在没有显式代理环境设置时自动继承系统静态 HTTP／HTTPS 代理；仅在进程启动时读取，不改系统或 Hermes 配置。空值优先、绕过列表及不支持的代理类型见[代理继承](docs/hermes-protocol.md#代理继承)。

主模型按会话、工作流运行和学习批次固定；顶层切换只影响新建任务和新发起运行，已有会话、后续节点和子流程保留原主模型，回退策略仍由 Hermes 管理。工作台不再使用本机 `defaultModel` 或 `WORKBENCH_HERMES_MODEL` 覆盖；需要原生策略确认的模型按界面提示到 Hermes 处理。

| 位置 | 用途 | Git |
| --- | --- | --- |
| 项目根目录 `workflow/` | 默认 cwd，首次启动自动创建 | 忽略 |
| `workflow/workflows/<id>/` | 每个工作流的定义、完整 AI 对话、素材与运行文件 | 忽略 |
| `workflow/artifacts/` | 普通会话产物 | 忽略 |
| `workflow/outputs/` | 保留旧交付副本 | 忽略 |
| `workflow/config/` | 本机资源覆盖与当前板卡配置 | 忽略 |
| `workflow/workflow-sessions/` | 各节点的隔离 Skill 会话与冻结 bundle | 忽略 |
| `workbench/.local/` | 现有 SQLite、Skill 快照、依赖与缓存 | 忽略，保留历史 |
| `workbench/workspaces/` | 旧会话和交付目录 | 忽略，保留历史 |
| 本机应用数据目录 `…/PersonalAgentWorkbench/runs/` | 保留旧执行原件、回执、节点版本 | 仓库外 |
| `skills/` | 内置 Skill、固件模板和 schema | 源码 |
| `hdk/learning/` 中的案例与答案 | 私人学习记录 | 忽略，通用 schema／说明除外 |

新任务的默认相对目录为 `.`，直接在 `workflow/` 工作。旧内置偏好 `default` 仅在旧默认布局升级时迁移一次，自定义配置保持；不批量搬移历史文件或改写审核。

迁移已有流程时，在软件的“运行前准备”中选择 `workflow/config/` 下的当前配置，清空旧的输出根目录即可继承新默认值。复制配置先校验内容 SHA，保留配置内已核验的资料路径；不要全局替换历史目录。已有学习合同与旧门禁仍可能被兼容能力引用，应保留其本机原件，不能为了清理目录重写哈希或删除学习记录。

每个工作流使用独立文件夹，编辑器可直接打开；新运行的原件与默认交付分别保存在自身 `runs/` 和 `outputs/`。`.workflow` 是包含目录内容的标准 ZIP 包，导入创建新副本。已有外部原件保留原路径、冻结记录和 SHA，迁移只复制归集；目录布局、资料完整性及导入历史只读规则统一见[工作流文件夹与便携包](docs/workflow-packages.md)。交付复制失败仍可单独重试，不重跑节点或人工审核。

## 代码边界

- `src/`：应用装配、HTTP/SSE、配置、偏好、持久化与适配器。
- `src/workflows/`：调度、文件、审核、版本、对话、学习及定时任务。
- `shared/workflow/`：前后端共用的纯模型、端口、规则、规划与数据契约。
- `shared/diagnostics.mjs`：有界诊断摘要与凭据脱敏，不裁剪实际运行数据。
- `public/`：页面、画布、DOM 交互与主题。
- `python/`：Hermes JSON-RPC、Skill 冻结与 Python 代码执行。
- `hdk/`：固定工程能力、转换器集成和验收；`skills/`：能力指令与资源模板。
- `test/`：Node、Python 测试及脱敏 fixture；`scripts/`：检查与转换工具。
- `examples/`：通用流程与数据集；`docs/`：操作、设计与维护说明。

依赖方向为“界面／后端 → 共享领域逻辑”。共享模块不依赖 DOM、HTTP 或数据库；静态服务仅提供白名单资源。旧 schema1 保留线性兼容，新 schema2 按依赖并行调度。

## 验证与发布

在本目录运行：

```sh
npm test
npm run check:git
```

测试入口固定为 `test/*.test.mjs`，所需 Python 测试由包装器调用。不要用裸 `node --test` 扫描常驻 fixture。

发布检查涵盖已跟踪与未被忽略的候选文件，同时检查真实个人主目录字面量；不修改暂存区、不上传。仅检查文件路径边界时可直接运行 `node scripts/check-git-boundary.mjs`。

一次性、绑定个人历史运行的工作流生成器已移除；实际流程从编辑器构建或导入用户自己的备份。测试构建器只存在于 fixture，不会生成业务产物。公开示例不包含本机板卡配置、黄金答案或学习结果。

## 应用诊断

软件调用故障可直接在原聊天检查Blender、FreeCADCmd和FFmpeg的位置、基础PATH及版本启动，并对Python节点做静态检查。macOS代码执行会按次补充已安装CLI的私有命令入口，原PATH优先，不改系统环境或已有节点。独立助手可升级来源绑定的总控只读诊断，在原聊天读取结论；同来源至多启动一次，不扩大写权限、不重放业务。发现、启动、语法通过与业务成功分别报告，详见[软件与脚本诊断](docs/application-diagnostics.md#软件与脚本诊断)。

右侧对话可主动发现真实应用能力，按需读取节点契约、执行环境、全局状态、运行错误、Hermes 工具记录和页面证据，并截图或短录制复现。无需手动复制应用已有说明或日志；流程修复及获准的业务代码配置在同一对话生成可审阅候选，应用和运行分别确认。截图使用专用只读浏览器。应用源码仅有默认关闭、人工开启的实验性总控修复入口，支持受限修改、隔离相关测试、记录与冲突保护回滚；不改或重跑真实工作流，不自动重启或发布，见[总控源码自修复](docs/application-source-repair.md)。

在“设置 → 助手权限”分别分配独立会话和总控助手的能力。独立会话固定在当前工作流及自身文件夹；总控可按开关取得跨工作流日志、软件日志和复制／新建测试流程／移入回收站能力。权限设置只由用户手动保存，AI 不能修改。目录与便携包权限见[工作流文件夹与便携包](docs/workflow-packages.md)，业务输出位置不会扩大助手范围；这些是助手接口限制，代码执行器不是 OS 沙箱。

诊断先使用紧凑摘要和已有证据，再补查详情；重复读取会去重，独立只读检查可批量请求。当前气泡显示实际阶段与耗时，失败和重启保留已完成诊断进度，按有效期和上下文校验复用证据，不自动重放操作。具体限制见 [上下文、进度与中断](docs/application-diagnostics.md#上下文进度与中断)。

新增功能同步维护能力目录、工具 schema／dispatch、内部 Skill 说明和回归。工具可用、仅能提案、仅界面支持和不可用分别声明；当前没有对外 MCP server，未来适配复用同一工具与权限实现。工具、依赖与验证边界见 [应用诊断说明](docs/application-diagnostics.md)，扩展流程见 [能力维护指南](docs/application-assistant-capabilities.md)。
