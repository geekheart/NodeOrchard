# 应用对话与诊断工具

工作流编辑器使用该工作流的独立会话；总控对话集中在“对话管理”页，按问题分成不同主题。两者复用聊天组件，后台按服务端身份调度工具，界面无需切换处理方式或打开独立诊断表单。说“检查最近一次为什么失败”后，助手先读取现有证据；需要修改业务流程时，在原对话展示经过编辑器校验的候选，点击应用。运行和人工审核仍经过现有入口与校验。

## 可调用的工具

以下为工具用途概览。实际能力状态、参数及调用权限由共享能力契约、当前工具目录和 dispatcher 决定；维护方法见 [应用助手能力维护与扩展](application-assistant-capabilities.md)。

| 工具 | 内容 |
| --- | --- |
| `app.capabilities` | 读取真实能力目录及依赖、提案与执行边界 |
| `node.describe` | 按需读取节点配置、执行和产物契约 |
| `runtime.inspect` | 检查当前执行环境与受支持依赖信息；不运行用户业务代码 |
| `runtime.software.inspect` | 受控定位Blender/FreeCADCmd/FFmpeg，分别报告安装发现、可执行、PATH可见及可选固定版本启动 |
| `runtime.code.check` | 绑定工作流、Python节点与可选冻结运行，按真实AST包装静态检查；显式变量可检查静态Python子脚本模板 |
| `conversation.escalate` / `conversation.escalation` | 独立会话登记或启动来源绑定的总控只读诊断，在原聊天读取进度与结论 |
| `assistant.skills.list` | 发现内部操作 Skill 的用途和版本 |
| `assistant.skills.read` | 按名称读取内部操作方法，供助手自动按需使用 |
| `assistant.diagnose` | 按归属聊天事项一次读取各次模型等待、输出、用量和完整性，不开放控制会话正文 |
| `assistant.trace` | 按已归属的轮次和调用分页读取有界请求链路元数据，缺失保持未知 |
| `assistant.experiment` | 人工开启后的总控合成近似模型实验；固定历史路由／推理配置与输入字符规模，不读取原始提示词或执行业务 |
| `assistant.probe` | 同轮固定模型的短请求探测，单轮一次；等待原生结果或用户停止，不执行业务、不重试原请求 |
| `workbench.inspect` | 只读检查设置、模型目录、定时任务与节点派生目录 |
| `app.state` | Hermes 状态、会话摘要、待处理请求及有限适配器错误 |
| `workflows.list` | 全局工作流列表，不要求先选择画布 |
| `workflow.inspect` | 当前草稿、保存版本与差异 |
| `workflow.run` | 明确选中的运行或最新运行、节点错误、时序、日志、部分输出和产物元数据 |
| `session.history` | 可见的工具调用和结果；旧会话从 Hermes 只读历史库读取 |
| `artifact.inspect` | 按登记 ID 检查产物归属、版本和哈希，按需读取小型文本 |
| `tools.catalog` | 应用工具与已缓存的 Hermes 工具目录 |
| `page.inspect` | 发消息时当前页面的状态、有限操作轨迹及请求错误 |
| `environment.probe` | 固定依赖的版本或 GitHub HTTPS 连接探测 |
| `browser.capture` | 专用只读浏览器中的真实截图、短录制、复现步骤、页面与网络错误 |
| `workflow.preflight` | 复用运行前检查，检查默认输入与文件，明确不等于实际节点执行成功 |
| `workflow.propose` | 生成经过编辑器命令校验的业务流程修改候选，在原聊天中应用 |
| `workflow.copy` / `workflow.create-test` / `workflow.delete` | 总控在明确授权下复制、创建测试草稿或移入可恢复回收站，不自动运行 |
| `app.logs` | 总控按权限读取持久分级软件日志；当前进程 Hermes 窗口单独标识 |
| `app.source.list` / `app.source.search` / `app.source.read` | 人工独立开启源码只读后，搜索和分页读取受控仓库及固定Hermes模块；不取得写入／测试权限 |
| `app.source.patch` / `app.source.test` / `app.source.history` / `app.source.rollback` | 人工另行开启实验性总控源码修复后，版本绑定修改、隔离相关测试与记录回滚，见[总控源码自修复](application-source-repair.md) |
| `conversations.list` | 总控读取工作流独立会话的有界目录摘要，不合并历史 |
| `conversation.inspect` | 按工作流读取有界脱敏消息和待处理元数据，不附带学习材料、节点代码配置或检查点 |
| `conversation.delegate` | 在明确授权和目标版本下提交只读诊断，返回任务身份后按需检查进度，不运行工作流 |

明确选中的旧运行不会自动替换成最新运行。诊断同时展示二者及当前草稿；例如旧运行 120 秒与草稿 300 秒属于不同事实。`partialText` 不是成功凭据。工具目录存在也不代表外部服务已经连通。

助手按需发现并加载内部能力 Skill，说明如何使用已登记接口；Skill 不新增权限。新增或改变产品功能时，应同步能力目录、工具 schema／dispatch、必要说明与同接口回归。界面已有功能、可生成提案和可直接调用的工具应分别标明；不能仅修改提示词就声称新增能力。

## 软件与脚本诊断

软件定位由 `src/application-software-inspector.mjs` 处理，只接受Blender、FreeCADCmd、FFmpeg三个标识。使用服务基础PATH，在macOS另查受控的系统／用户Applications路径；返回安装发现、可执行、基础PATH可见和选中CLI路径。未发现只表示本次受控搜索没有命中，不代表全盘未安装。FreeCAD只找命令行程序，不用GUI启动器代替。

代码执行器通过 `workflows/workflow-runtime-launchers.mjs`复用同一发现器，在每次macOS代码worker的私有临时目录补固定命令别名，追加在原PATH末尾。现有同名命令优先，Python的shutil.which与JavaScript子进程均可找到应用目录中的CLI；不用修改节点代码、系统PATH或安装软件。别名以exec启动真实可执行路径，保留参数与进程组；使用临时HOME／XDG，FreeCADCmd另设offscreen。完成、失败或取消后清理本次入口，执行超时及进程组停止保持。`pathVisible`只表示基础PATH，本次准备的别名记录在节点runtime.softwareAliases，不含本机路径；准备不证明程序已启动。其它平台保持原PATH。此能力与只读版本探测分开，不自动重跑旧运行。

`verifyLaunch:true`仅以固定参数启动版本命令，使用临时HOME、最小环境、时间和输出限制，不打开用户文件、改PATH、安装依赖或执行用户脚本。启动失败返回白名单错误类别，不透传原始stderr、环境或凭据。版本可启动与实际导入、STEP转换、渲染分别验收；受限测试环境的Qt／CPU报错不能自动归因为软件安装损坏。代码执行进程及版本探测均不是OS沙箱。

`runtime.code.check`只从获准工作流的Python节点读取代码，可指定原始普通业务运行的冻结快照；没有任意路径或模型提交代码入口。返回节点、来源、代码SHA和有界语法错误。`python/workflow_code_validation.py`供真实worker与静态检查共同使用：AST函数包装保持多行字符串原值，静态路径只parse／compile，不exec、不导入业务依赖。`pythonScriptVariables`只显式检查单次赋值的静态Python字符串，replace模板只检查替换前内容；动态脚本标不可确认。默认不把海报文案等多行文本当Python。静态通过不能证明业务正确或产物成功。

独立助手在本轮已分类为诊断的用户请求下，可用 `conversation.escalate`登记来源工作流／轮次绑定的总控任务；`start:true`最多启动一轮子诊断并产生真实模型用量，默认仅登记。来源身份由服务端给定，摘要有界脱敏，不能指定他人工作流、转发学习材料或赋予写权限。启动要求当前独立会话可读，且总控已有工作流、跨工作流和软件日志读取权限；不足时保留blocked状态，不创建子会话，不要求开启源码修改。源码只读仍单独按人工配置决定。

升级记录按来源轮次和操作内容校验幂等；同来源换操作ID不会重发。子消息在独立总控主题持久化，固定 `readOnly:true` 与服务端 `workflowBound:true`：业务工作流、运行、会话、素材、文件夹及截图均锁在来源工作流，仅结构化软件日志与获准源码只读保留全局实现证据。不带其它主题历史、旧检查点或写操作授权；即使人工开启源码修复，子诊断仍不能patch、测试、提案、运行、学习、审核或反向委派。停止、失败或重启不自动重放。`conversation.escalation`在原聊天按任务ID、来源轮次或最近任务读取脱敏结论与阶段，不展开子任务工具结果或源码。任务complete表示诊断结束，业务修复继续由原会话生成可审阅候选。

软件和静态检查证据仅在本轮按实际请求复用，不跨轮恢复；升级状态每次实时读取，不从检查点恢复旧进度。搭建请求仍先经AI分类进入候选分支，命名软件的本地依赖定位不触发诊断模型链；候选生成器接收有界软件位置与语法证据，保留候选、应用和运行的区别。

总控子诊断作为后台任务，来源轮正常完成后继续保留；用户中断来源聊天时同步中断该来源的子任务。启动占位阶段的中断先持久化，迟到回执不得恢复started，已接收子任务立即收到中断；已中断身份不会重放。总控主题原有停止入口继续有效。

## 自由对话的AI分类

两个对话入口对普通自由消息先调用 `assistant-intent-classifier.mjs`：只提供当前消息、工作流是否为空和少量类型／状态摘要，不提供工具schema、业务代码、日志或完整能力目录。模型只返回类型，默认不设置本地等待截止；无效响应、用户取消、连接中断或上游返回错误时明确终止，不擅自改为诊断。模型路由在分类前固定，后续处理沿用同一路由和轮次身份。

创建／修改进入专用候选生成器，正常路径为一次分类加一次候选生成；诊断才进入工具编排。反馈及长期改进先准备已有版本绑定的动作，不因分类自动执行。明确运行、审核和聊天事项结束命令仍走原有精确身份校验。分类不是用户授权，权限及只读委派边界始终由服务端执行。

候选上下文对简单流程提供基础节点、当前图所用节点和相关工具／Skill契约，复杂流程回退完整契约。省略数量明确标识，不把省略当作能力不存在。需求只提供一次，历史去重并有界，保留当前固定Skill版本、原有图校验和一次候选纠错。图片产物仍保留人工审核，文件必须真实生成和登记。

受保护助手仅在本轮已明确固定 `modelRoute.provider=openai-codex` 时，为工作流候选生成通过 Hermes 原生 `session.create.reasoning_effort` 选择 `medium`。其它或未知路由不传该覆盖，继续继承 Hermes 配置；这不是面向所有提供商的通用推理策略，不改默认模型、提供商或全局配置。Codex 候选提交前等待原生非 lazy 的 `session.info`，核对模型身份、实际推理档位及 wire 档位；未确认则停止并释放新建的空会话。分类、普通诊断和学习评估也不使用这个局部覆盖。诊断记录仅投影请求／读回／wire 的枚举值，旧记录缺失保持未知，不读取或返回内部思考。普通提供商的 `reasoning_effort_wire` 是 Hermes 入口映射，后续传输层仍可能调整或省略该字段，不能据此声称实际已发送某个档位。

## 上下文、进度与中断

首轮上下文包含所选运行、最新运行和当前草稿的紧凑摘要，保留对象身份、版本、节点状态、错误及省略标记。代码、运行日志、会话历史和能力详情通过工具按需读取，仍受各接口的容量限制；已提供的证据先使用，缺少什么再补查什么。紧凑摘要不代表被省略的内容没有错误，也不改变原始运行记录。

总控主题分别保存上下文与检查点，工作流会话彼此独立。目录用于定位目标，其余会话正文按需读取；主题切换不继承另一主题的操作授权。只读委派保留来源主题和目标消息身份，提交成功只说明诊断已派发；子助手完成、业务修改应用和运行验收仍是不同状态。详细边界见 [全局对话管理与委派](application-assistant-capabilities.md#全局对话管理与委派)。

模型可以一次请求最多四项独立的只读检查。调度器先验证整批名称和参数，再按顺序执行；任何不允许批量的请求会使整批拒绝。提案、浏览器采集和网络探测不进入批量路径。同一轮中，相同工具及规范化参数复用已完成的结果，避免重复取证；批量和复用继续经过原有工具权限与对象校验。

当前聊天气泡显示正在读取状态、准备模型、等待响应、读取结果、检查工具或生成方案等实际阶段，并记录开始时间、耗时、调用数及已完成步骤。分类、应用助手、候选生成、模型探测和学习评价默认均不设置本地首响应、输出空闲或整轮时间截止；等待 Hermes／提供商返回完整结果、错误或用户停止，不因经过180秒、静默60秒或整轮六分钟主动中断。进行中仍显示实际阶段和耗时。诊断策略中的期限及 deadlineAt 明确为 null，表示本地限制已关闭；历史有数值的策略保留原值，旧记录缺失不能改称无限。显式有限控制参数仍可供隔离测试或固定调用者使用，普通产品入口不注入它们。连接启动与 RPC 确认、业务节点自身配置、外部工具／子进程的执行期限保持独立，不调整用户工作流。用户停止、断线与应用关闭仍结束等待，保留进度和不确定回执，不自动重放。上游超时报告实际错误，不能仅凭无正文判断服务端排队、推理或网络故障；部分输出仍不等于生成完成。

脱敏的诊断步骤、工具回执与有界结果随当前事项保存；失败、停止和服务重启保留已完成证据，并标记中断的步骤，不自动恢复模型或重放工具。后续消息只从服务端已保存记录选择检查点，经对象、草稿指纹、运行证据、模型路由、能力版本及当前工具契约校验后，才复用仍在有效期内的只读结果。每条结果按自己的采集时间过期，阶段更新不会延长其有效期。

跨轮业务证据只复用当前摘要覆盖的工作流版本与草稿图，以及所选或最新的已结束运行；其它目标重新读取。会话历史、Hermes 缓存工具目录、活动运行、页面、环境探测、采集、预检和产物读取不跨轮复用，避免独立变化的内容被当作当前事实。能力契约与固定运行时观察仍按各自范围和有效期校验。

修改方案的模型调用异常会结束本轮并保存进度，外层不会在同轮再次请求同类方案。已有提案仍经过编辑器验证与用户应用入口；证据检查点不授予应用候选、执行业务或修改源码的权限。

## 模型调用诊断与探测

助手对话本身失败时，优先 `assistant.diagnose`，无需通过多次日志和历史查询拼装模型时序。结果的 `currentPolicy` 仅表示当前默认值，历史 `calls[].timeoutPolicy` 缺失保持未知；未终止输出与零计量帧不当作零成本。新 `application_model_calls` 仅保存阶段、计时、字符数和终止分类；历史字符数由固定只读RPC补充，不返回提示词、正文、推理、配置或凭据。独立助手仅自己的工作流，总控另需软件日志及相应跨对象权限。旧在途快照与当前所属事项状态分别投影，不伪造模型完成时间。

`assistant.probe` 通过已有受保护控制器发起固定短请求，使用本轮固定模型，默认等待原生返回或用户停止。不能批量、任意指定模型或提示词、同轮重复或跨轮缓存；只读委派不提供探测。短请求通过仅证明当前短请求可完成，不代表原复杂任务已恢复。编排每轮告知剩余工具、决策与等待策略；查询额度耗尽后只进行一次最终答复，不反复尝试被拒绝的工具。

`workbench.assistant.diagnostics` 仅接受经Node按轮次核验后映射的1至12个存储会话身份，在Hermes固定启动库上使用原生只读句柄。SQL仅提取字符数量、消息数、完成标记与数字用量，不创建agent、不恢复会话，不接受路径、查询或profile。

## 请求级链路与近似实验

新的受保护助手调用将控制 `requestId` 传入原生准备接口。原生仅对该助手实例的SDK客户端挂接HTTP元数据观察；不修改Hermes源码或全局HTTP客户端，不采集普通工作流、第三方请求或正文。`model.request.trace` 进入Node专用校验入口，不原样转发SSE／浏览器历史；按已登记控制会话与请求身份写入 `application_model_request_traces`，最多1000条、4MiB和14天。每次控制调用至多32个实际HTTP请求，阶段更新有界，原始流不逐块落库。

观测含HTTP状态、白名单 `x-request-id`／`request-id` 值、数字Retry-After、连接与TLS阶段耗时、响应头及首末body字节相对时刻、固定SSE事件类型计数，以及固定错误分类。DNS无法独立观测；connect可能含DNS与代理，tlsMs为观测到的普通连接及代理隧道TLS阶段总和，不拆分端点或声称仅目标服务器TLS。SDK复用连接或不支持的客户端可能缺少阶段，明确返回 `unavailable`，不把缺失当零。SSE在受保护SDK已有的iter_bytes解码后观察，支持该SDK可解码的压缩响应，缓存重读不重计；每请求新增观察最多8MiB解码字节，超额后清空计数并标为不可观测／截断，原数据继续交SDK。此额度限制新增观察开销，不限制SDK自身解压或请求输出。原始流EOF只描述传输，SDK读到结束标记后可正常提前关闭；模型完整性仍按原生终态与完整结果核对。应用取消来源与传输错误分开，控制器abort不擅自细分为用户／系统原因。

`assistant.diagnose` 默认附紧凑请求摘要，完整细节通过 `assistant.trace({workflowId|conversationId,turnId,callIndex,afterRequestIndex?,limit?})` 逐页读取，limit为1至4。工具直接按真实调用编号核对持久归属（编号不受摘要12条限制），分页不重复读取原生历史元数据，不缓存活动请求快照；不接受任意session／文件路径；重启前未采集的历史请求不能补造。requestCount指当前保留的请求记录数，不是历史请求总数；coverage说明序号缺口、保留限制和采集上限。记录保留窗口或采集上限可能使详情不完整，仍按具体证据与缺口解释。

总控的 `sourceRead` 和 `modelExperiment` 为人工独立开关，默认关闭且旧配置不自动扩权。源码读取与修复权限分开，实验额度和一次准入的执行模块固定保护，不能借源码修复自行提高额度。实验设置 `modelExperimentLimits.maxInputCharacters` 默认50000，人工范围1000至100000；每个总控轮次最多一次应用模型调用，持久准入阻止重启／停止／失败重放，不将原生SDK内部HTTP重试计为新增工具调用。

`assistant.experiment` 必须指定已登记历史turnId与callIndex；先核对目标归属、已确认模型／提供商／推理配置和字符规模，仅发送固定合成内容。超过人工输入额度、历史规模过小或配置未知则明确不可用，不缩小样本或读原始提示词。新会话准备后再次核对实际推理配置，不一致时不提交模型请求。它没有业务工具，不生成或运行工作流；真实模型用量仍会发生，输出长度只靠固定短JSON指令软约束，不能声称有Token／费用硬上限。比较结果只检验路由与字符规模，不能替代原任务语义和真实Token分布，不能证明历史唯一根因。实验默认无本地时间截止，可手动停止；权限改变立即结束，已有准入不会自动续发。

请求格式枚举仅表示头部声明的MIME与编码，不能保证上游未错标。缺少MIME时，在同一观察额度内检查解码流的SSE帧边界，遇到完整事件帧才启用计数；格式枚举仍为unknown，不保存data内容。明确声明JSON／其它格式时不探测。SSE不可观测原因分别标为not-event-stream、decoded-stream-unobserved、observation-limit、parser-error或unknown；旧记录没有这些字段保持unknown／null。源码只读提供有界literal搜索 `app.source.search`，用于先定位符号行号再分页读取，避免反复列目录耗尽诊断额度。

新请求的 `sse.eventTimings` 记录白名单事件完整帧被解码观察到的 `firstMs`／`lastMs`，均相对该次HTTP请求开始。相同解码块内的多帧可能同一时刻，不是服务商的生成时刻；历史未采集时为null。结合应用首次输出时刻，分别判断响应头前、已接收控制／推理事件但尚无正文、正文流及最终读回的耗时。只有累计计数的旧记录无法补造这条时间线。

`error.causeChain` 最多六项，仅保留限定异常类名、白名单OS错误数字及符号；未知类收敛为unknown，循环或超长由 `causeChainTruncated` 标记。SSL和DNS自有编号不按OS errno解释。无原始异常消息、参数、端点或配置；历史缺失保持null。即使观测到ECONNRESET，也只证明连接重置，不能凭它认定责任在本机、代理或服务商。

第三方可能抑制最终异常的底层原因。`transportFailures` 独立记录最多四个固定httpcore失败阶段、相对时刻及当时的受限原因链，避免事后从已抑制的异常补猜。只允许连接／TLS，以及HTTP/1.1或HTTP/2的请求头、请求体、响应头、响应体、关闭阶段的 `.failed`；不保留原异常对象或其它trace info。重复阶段覆盖及超过四阶段时 `transportFailuresTruncated=true`。它不拼接或改写最终异常链；空数组仅表示未捕获这些阶段的失败，旧记录及不可观测请求为null。仍使用每条8192字节和原快照额度，不扩大采集窗口。

`sdkRetryPolicy` 仅在实际SDK客户端的 `max_retries` 数字可读时记录；每个HTTP请求冻结一次，未知为null。它与应用层是否自动重试、Hermes内部流恢复分别解释。一次逻辑模型调用可包含多个HTTP请求：按同一调用身份逐次读取，区分失败尝试、观测的请求间隔、后续成功请求，避免将整个输出区间当成一次连续流；不从间隔长度猜固定退避策略或重复计费。

核对原生重试实现时，`app.source.read/search` 的固定 `component` 入口只开放指定Hermes模块，与仓库 `path/prefix` 互斥，继续受源码只读开关约束。它不读取安装配置、凭据或任意文件；当前模块SHA与实际调用时观测的客户端策略分开报告，不能把静态代码当作已确认的动态配置。具体组件及分页见[诊断源码读取](application-source-repair.md)。

## 截图与录制

诊断浏览器使用独立 Chrome profile，只访问应用的本机地址。真实用户标签页、其它应用和整个桌面不在采集范围内。新浏览器的临时界面状态可能与当前用户页面不同；回答和附件明确标注 `isolated-readonly-browser`。

通过 CDP 获取真实 PNG，支持有限的应用路由导航、明确按钮点击与滚动。短录制最多 10 秒、约每秒 3 帧，使用本机 ffmpeg 编成 MP4；没有编码器时提供真实 PNG 帧及时间清单，不能宣称已经得到视频。Hermes 接收最多四张真实图像关键帧与操作、错误记录进行分析，不依赖模型直接理解 MP4。

默认查找本机 Chrome 和 ffmpeg；可通过 `WORKBENCH_DIAGNOSTIC_CHROME`、`WORKBENCH_DIAGNOSTIC_FFMPEG` 指定可执行文件。缺少依赖或权限时工具明确返回不可用。截图、录制、清单及临时 profile 位于私有 `dataDir/diagnostics/`，不会提交到 Git。附件只通过登记的 ID 与文件名读取。

诊断代理只放行白名单同源 GET，拒绝业务写请求、会话恢复、事件流及外部访问。输入框、私人区域、属性和学习区域在截图中遮蔽；学习运行及其样本产物不能经诊断读取。只读复现不能覆盖需要真实提交、系统权限或外部服务写入才能出现的问题，此时应交代缺失条件。

## Hermes 边界

应用助手使用单独的托管模型会话与 `workbench.assistant.prepare`，不会放开学习评估会话的工具权限。Hermes 在此会话没有原生 shell、文件修改、Skill 修改或记忆读写能力；模型提出工具请求后，由 Node 后端的白名单调度。没有任意命令、任意文件路径或源码补丁接口。

`workbench.assistant.images` 仅接收诊断根目录内的图片，验证类型、数量、大小和真实路径后把图片内容交给模型。`workbench.assistant.history` 直接打开只读历史库，不创建 agent、不恢复或重放任务。内部推理字段、凭据与学习答案在证据投影中剔除；不在每轮上下文灌入完整日志。

应用助手当前支持普通 Hermes 模型连接，包括已配置的 Codex Responses 订阅连接。`codex_app_server` 有独立执行通道，不能遵守这里的工具边界，因此明确拒绝用于应用诊断。业务工作流的执行权限沿用现有机制；这里不把已有代码节点或普通 Skill 的执行器宣称为操作系统沙箱。应用自身代码缺陷应交付诊断证据与修复建议。

源码保护不禁止用户授权的业务代码候选。已有代码节点可按其真实契约提出可审阅配置；应用草稿和运行分别经过原有校验。助手应先读取能力说明及应用已有证据，避免把缺少专用注册工具误判为通用代码能力也不存在。

当前没有对外 MCP server。未来协议适配复用同一工具 schema、dispatcher 和权限实现，不提供另一条权限更宽的调用路径。

停止、断线或重启不会重放上一轮操作；相同消息 ID 只读取原记录。对话里的“已检查”表示相应工具完成，不代表业务问题已经修复。结论应说明证据、推测、实际修改及验证状态。
